0. 怎么用这份总结

  1. 先看信号，再选算法。每节开头是「适用信号」——题面出现这些特征，就往这一节翻。
  2. 复杂度是硬约束。同一题 O(n²) 与 O(n log n) 的差别，通常就是能不能过的差别。
  3. 代表题不是题解。表格只给「题号 → 关键点」，细节回 LeetCode 对应题目页看。

2. 基础数据结构与操作

2.1 数组与字符串

本质：连续内存 + 下标寻址。下标之差就是「距离」，下标本身就是状态。

适用信号：输入是一维序列；要求统计、比较、变换某个连续段；要求原地改。

必会套路

套路 做法 复杂度（时间 / 额外空间） 备注
原地重排 快慢指针一趟扫描，不满足条件的就往后挪 O(n) / O(1) 只保证「元素集合不变」；要保序得靠写指针逐个前移
前缀积后缀积 两趟遍历，不用除法避免除零 O(n) / O(1) 避开「数组含 0」和整除截断；要求入模时不能先取模再乘
最大子段和 Kadane：要么 DP，要么分治 O(n) / O(1) O(n)/O(1) 指 Kadane 版；分治版是 O(n log n)，栈深 O(log n)
找重复/缺失 原地打标记（下标当桶），或异或 O(n) / O(1) 打标记要求值域在 [0,n) 且非负；异或只适用「其余成对出现」
字符串窗口 窗口内维护字符计数 O(n) / O(1) 字符集固定时用定长计数表；按 Unicode 切分才需转 []rune，额外 O(n) 空间
长串子串比较 滚动哈希（自然溢出）+ 双哈希防碰撞 O(n) / O(1) 哈希是概率正确；要求严格正确改用 KMP / Z 函数（O(n) 空间）

表中 n 指输入序列的长度；复杂度一栏统一是「时间 / 除输入外的额外空间」，不是针对数组或字符串本身。

2.2 哈希表与计数

本质：用「键 → 值」把查找从 O(n) 压到 O(1)。本质是用空间换时间，也是「记录已访问」的通用手段。

适用信号：需要判断重复、需要统计频次、需要记录「上次出现位置」、需要 O(1) 判存在。

必会套路

套路 做法
找配对 边遍历边查表，不要先全存再查
频次统计 map[K]int 计数 + 一次遍历取最大/最小
位置记录 map[K]int 存下标，用下标差算距离
分组 map[K][]T 或先给键编号再开桶
连通性 并查集，见 4.4

2.3 排序

本质：把数据按全序排好，让「相邻」变成一个可用的信息源。

适用信号：需要第 K 大/小；需要按位次处理；需要「排序后相邻配对」；要求稳定性的自定义比较。

必会套路

套路 做法 复杂度（时间）
快速排序 partition + 双指针 期望 O(n log n)
归并排序 分治 + 合并；顺带求逆序对 O(n log n)
堆排序 建堆后反复取顶 O(n log n)
计数排序 值域有限时用桶 O(n + k)
第 K 大 快选（平均 O(n)）或大小为 K 的堆 O(n log K) —
自定义比较 多关键字时显式写比较器，别依赖排序稳定性 —

2.4 链表

本质：节点串成的链，访问靠指针，插入删除 O(1) 但定位 O(n)。

适用信号：题目给出 head / 节点结构；要求反转、断链、合并；出现「倒数第 k 个」「找环」「找交点」。

必会套路

套路 做法
虚拟头节点 dummy := &Node{}，消除「头节点特殊处理」分支
快慢指针 找中点、判环、找交点都靠它
反转链表 三个指针原地翻转；递归版要注意栈深
合并 按值大小顺序接指针
前后缀 反转后半段，再原地接回

2.5 栈与队列

本质：栈是「后进先出」，队列是「先进先出」。两者都是只暴露一端的结构，于是「最近满足条件的元素」能被高效拿到。

适用信号：括号匹配、表达式求值、单调性维护、层序遍历、固定窗口最值。

必会套路

套路 做法 复杂度（时间）
单调栈 存下标，入栈前把不满足单调性的弹出 每个元素各进出一次，O(n)
单调队列 双端队列存下标，队首永远是当前窗口的最优 O(n)
括号匹配 左括号入栈，右括号出栈比对 O(n)
表达式求值 数字栈 + 运算符栈，或单栈 + 符号位 O(n)
层序遍历 队列按层推进，记 len(q) 切层 O(n)

2.6 字典树

本质：把公共前缀合并成一棵树，让「前缀查询」退化成沿边走。

适用信号：大量字符串、查询以字符串前缀出现；统计以某串开头的数量；实现自动补全。

必会套路

  • 节点存子节点 map + 结束标记 + 计数（计数用来做前缀统计）
  • 插入 O(L)，查询 O(L)，L 为串长；空间 O(总字符数)
  • 想省空间可以把 26 个孩子压成数组或位集

2.7 堆

本质：维护「当前最值」的容器。push/pop 是 O(log n)，取顶是 O(1)。只保证堆顶有序，不保证整体有序。

适用信号：Top K、第 K 大/小、流式最值、多路归并、任务调度。

必会套路

套路 做法 复杂度（时间）
Top K 大小为 K 的小根堆，扫完取顶 O(n log K)
第 K 大 大小为 K 的小根堆，或快选 O(n log K) / 平均 O(n)
流式最值 固定大小堆，边来边挤 O(log K) 每次
多路归并 K 个有序序列各取堆顶 O(N log K)
任务调度 贪心 + 冷却时间统计 —

3. 基础算法

3.1 二分查找

本质：在单调的判定上做对数级收敛。前提不是「数组有序」，而是「答案落在左边或右边，且能 O(1) 判定」。

适用信号：答案空间是整数区间；要求最小值/最大值满足某条件；有序数组找边界。

必会套路

套路 做法
值域二分 在 [lo, hi] 上二分，判定函数单调
判定二分（最大化最小值 / 最小化最大值） check(x) 可 O(n) 判定，二分 x
找边界 lower_bound / upper_bound 手写，注意 mid 偏哪边
旋转数组 先找断点（一个 O(n) 判断），再在对应半区二分
浮点/开区间 用 while lo < hi + mid = lo + (hi-lo+1)/2 避免死循环

代表题

题号 标题 难度 关键点
0033 Search in Rotated Sorted Array Medium 每次判断哪半边有序
0034 Find First and Last Position of Element in Sorted Array Medium 两次二分或一次二分双边界
0875 Koko Eating Bananas Medium 判定二分：速度 x 能否吃完
0410 Split Array Largest Sum Hard 判定二分：段和上限 x 是否可行
0004 Median of Two Sorted Arrays Hard 二分在较短数组上切，保证左半不小于右半

易错：mid 取下整还是上整，要和 hi = mid / hi = mid - 1 配套；混用就死循环。

3.2 滑动窗口与双指针

本质：把 O(n²) 的枚举「对撞」压缩成一次扫描。关键是定义好循环不变量：窗口里已经满足什么。

适用信号：连续子数组/子串的最长最短；需要「窗口内不重复/不超限」；两数之和的变体。

必会套路

套路 做法 复杂度（时间）
固定长度窗口 右扩左缩，窗口长度固定 O(n)
可变长度窗口 右扩，条件破坏就左缩到刚合法 O(n)
对撞双指针 首尾夹逼（3Sum、盛水容器） O(n)
快慢指针 同向不同速（判环、去重） O(n)
跳过/原地 写指针与读指针分离 O(n)

3.3 前缀和

本质：把「区间求和」从 O(n) 变成 O(1)：区间和 = 两个前缀相减。

适用信号：问连续区间的和/和的某个性质；「和为 K 的子数组」；二维矩形区域和。

必会套路

套路 做法
一维前缀和 pre[i+1] = pre[i] + a[i]，区间 [l,r] 和 = pre[r+1]-pre[l]
前缀和作键 map[sum]count，边遍历边查差值
前缀积 同理，注意 0 的处理
二维前缀和 建 pre[i][j]，矩形和 = 四项容斥
前缀异或 pre[i]^pre[j] 得区间异或

3.4 递归与分治

本质：把大问题拆成同类小问题。递归是表达「规模递减」，分治是「拆 + 合并」。

适用信号：题面有「在区间里选」「合并两个有序序列」「求中位数」；需要把 O(n²) 降到 O(n log n)。

必会套路

套路 做法
归并 分到底再合并，合并时顺手统计跨区答案
折半 二分下标 + 一次 O(n) 判定
递归三要素 终止条件、递推式、答案合并方式
记忆化 同一状态只算一次，键要选对
快速选择 partition 递归，只递归包含第 K 位的一侧

4. 遍历与图

4.1 深度优先搜索

本质：一条路走到底，走不动了回退。适合「把一个答案空间枚举完整」。

适用信号：连通块计数、枚举所有可能方案（选/不选、放置）、路径搜索、依赖关系判环。

必会套路

套路 做法
连通块 网格/邻接表上 DFS，每找到一个未访问节点计数 +1
回溯 维护「路径」，做选择 → 递归 → 撤销选择
拓扑判环 DFS 三色标记：未访问/在栈上/已完成；遇到在栈上的节点即有环
剪枝 状态重复就停（记忆化）、答案已最优就停
方向枚举 四方向 / 八方向的偏移数组统一写

4.2 广度优先搜索

本质：按距离分层扩展，第一次到达即最短（无权图）。

适用信号：求最短步数/最短距离；按层输出；状态空间是一张隐式图。

必会套路

套路 做法
层序遍历 队列，按 len(q) 切层
最短路（无权） BFS，第一次入队时记距离
状态压缩搜索 队列里存状态编码（位掩码、坐标对）
双向 BFS 两端同时扩，状态空间大时省一半
多源 BFS 所有起点一起入队，等价于加一个超级源点

4.3 树

本质：层级结构，天然递归。关键只有三个：定义清楚节点含义、确定返回什么、区分左右孩子的处理次序。

适用信号：题目给出二叉树 / BST；求路径和、深度、直径、LCA；需要序列化。

必会套路

套路 做法
递归三状态 返回值（向上汇总）+ 参数（向下传递）+ 副作用（外部变量）
BST 性质 左小右大；中序遍历有序；验证时带上下界
路径问题 回溯累加路径和，回溯时减掉
直径 / 最大路径和 左右子树高度返回值 + 全局变量记录答案
层序遍历 队列，或 DFS 带上深度参数
序列化 前序 + null 标记，天然可还原

5. 范式与技巧

5.1 贪心

本质：每一步都选当前看来最好的，靠「局部最优能推导出全局最优」的证明支撑。没有证明的贪心就是碰运气。

适用信号：要求最大值/最小值且答案可以逐步构造；区间选择类；排序后按序处理。

必会套路

套路 做法
排序贪心 按某个键排序后按序处理（区间调度、糖果分配、任务冷却）
交换论证 证明「把最优解里的两个元素交换不更差」，从而局部选择成立
反悔贪心 先按基线选，再回头修正（任务调度、合并区间）
贪心 + DP 贪心定顺序，DP 定数量（如 1335）
区间选择 按右端点或左端点排序，贪心取不冲突的

5.3 动态规划

本质：把「答案依赖什么」写成状态。DP 的全部难度在于状态定义对不对，不在于转移怎么写。

判定要不要用 DP：三个信号一起看——① 求最优解或计数（要列出全部方案时用回溯，不是 DP）；② 存在重叠子问题；③ 无后效性（当前决策不影响后续规则）。第三条最关键。

8. 选型速查

8.1 特征 → 算法

题面特征 先想到 常见变体
有序数组找位置/边界 二分查找 旋转数组先找断点
求最小值/最大值使某条件成立 判定二分 check(x) 必须单调，且能 O(n) 判定
连续区间内的最长/最短/计数 滑动窗口 固定长度 vs 可变长度
窗口内要不重复/不超限 滑动窗口 + 计数 「至多 K」减「恰好 K」
需要记录出现过什么 哈希表 键必须是不变量
求「第 K 大/小」 堆或快选 流式多次查询只能用堆
括号匹配、表达式求值 栈 中缀求值要数字栈 + 符号栈
下一个更大/更小元素 单调栈 存下标才能算宽度
固定窗口内的最值 单调队列 队首恒为窗口最优
最短步数、分层输出 BFS 无权图首次到达即最短
枚举所有方案、找环 DFS / 回溯 忘记撤销状态是头号错因
区间最值、区间和查询 前缀和 二维用四项容斥
区间和等于 K 前缀和 + 频次表 「恰好 K」=「至多 K」减「至多 K-1」
树上的路径和/深度/直径 树形递归 直径要额外一个全局量记答案
最近公共祖先 BST 用大小关系；普通树用左右返回 别只比较父子
区间调度、选最多不冲突区间 贪心 按右端点排序
每步取当前最优且可证明 贪心 必须给交换论证
求最优解且有重叠子问题 DP 先定状态，再写转移
要列出方案本身 回溯 只要个数就别回溯
元素个数 ≤ 20 的组合问题 状压 DP mask 表示选了哪些
每件物品只能取一次 0/1 背包 容量倒序遍历
每件物品可重复取 完全背包 容量正序遍历
只出现一次 / 恰好出现 k 次 位运算 x^x=0、x&(x-1)
数值很大、要精确算 快速幂 / 闭式公式 O(log n)
多个操作、要求每次 O(1)/O(log n) 设计类 先写暴力再优化
只要唯一解 / 存在性 位运算、数学、哈希
给表结构、返回一张表 SQL WHERE 过滤行，HAVING 过滤聚合

8.2 数据范围 → 复杂度上限

先看 n 卡掉不可能的解法，剩下的一两个家族里再比实现细节。

数据范围 可接受的上限 该往哪想
n ≤ 10 O(3^n) 枚举三元组、暴力回溯
n ≤ 20 O(2^n) 状压 DP、位掩码枚举、回溯剪枝
n ≤ 50 O(n³) 三重循环、朴素区间 DP
n ≤ 1000 O(n²) 二维 DP、枚举所有区间
n ≤ 10^5 O(n log n) 排序、二分、单调栈/队列、堆、树状数组
n ≤ 10^6 O(n) 前缀和、哈希、双指针、单调栈、并查集
n ≤ 10^9 O(log n) 闭式公式、筛法、数学、快速幂
n ≤ 10^18 O(log n) 矩阵快速幂、模运算

最后两行说的是数值不是元素个数：元素个数受内存限制，数值才是大数问题。常数的差异也会影响排名——n 到了 10^6，哈希查表和排序的差距会明显拉开。

8.3 容易选错的两组算法

容易混 区分信号 选错的症状
滑动窗口 vs 前缀和 窗口内要「满足条件」还是只要「区间和」 用前缀和处理「不重复」，得不到不重复的最长子串
二分 vs 双指针/哈希 数组是否真的有序 数组无序却写二分，边界必错
判定二分 vs 直接贪心 目标是不是「最小/最大可行值」 贪心算不出「最小速度」这类答案
DP vs 回溯 要「个数/最优值」还是「方案本身」 回溯求个数，指数级超时
贪心 vs DP 局部选择会不会封死后面 区间选择类能写但证明不了，等于没写
堆 vs 快选 一次性静态数组 vs 流式多次查询 静态数组反复上堆，复杂度白给
DFS vs BFS 要「全部方案」还是「最短步数」 求最短路用 DFS 会指数爆炸
并查集 vs DFS/BFS 只判连通性还是要具体路径 并查集给不出路径
递归 vs 迭代 输入链/树的深度上限 n = 10^5 的链式输入递归必爆栈
哈希 vs 排序 要不要保序、要不要最值 用哈希求「最小的那个」无从下手
0/1 背包 vs 完全背包 物品能不能重复取 遍历顺序写反，答案偏大或偏小

8.4 提交前自检清单

  • 复杂度对照 8.2 的上限，超标就换家族，别在实现细节上硬抠。
  • 递归深度：链状输入（n = 10^5）改显式栈迭代。
  • 溢出：Go 的 int 是 64 位，但 int32 量级的两数相乘、1 << k 仍会溢出；移位前先转 uint。
  • 哈希键必须不可变；map 的值可以是 slice，键不行。
  • 输入是否真的有序？题目没保证就别依赖有序。
  • 边界各写一条测试：空输入、单元素、全部相同、最大规模。
  • 滑动窗口：收缩条件是「不合法就缩」还是「缩到刚合法就停」。
  • BFS：入队即标记已访问。
  • 回溯：每一层都撤销状态。
  • 背包：0/1 倒序容量，完全背包正序容量。
  • 贪心：写不出交换论证就改成 DP。
  • SQL：WHERE 过滤行、HAVING 过滤聚合；LEFT JOIN 的 ON 条件写错会放大行数。
  • 别只拿样例当期望值：期望值用规则或独立实现推导，别手写常量。
