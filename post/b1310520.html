Dify 本地填坑记录

概述

记录 MacOS 上相关的 dify 调试坑点及填坑过程。

相关参数：

  • MacOS: 26.5.2
  • Dify: 1.16.1

坑点见下方列表：

  • /docker-entrypoint-mount.sh文件映射问题
  • 模型设置接入异常
  • 工作流下标溢出
  • APIKey无效
  • 模型provider如何重新配置
  • 订阅并导入了Plan却没在Dify找到对应的模型
  • dify上embo-01模型向量化失败

/docker-entrypoint-mount.sh文件映射问题

  • 原因：nginx/ 下的所有文件都是空目录。
  • 方案：下载 dify 仓库的整个docker/目录，而不是只拿到个docker-compose.yaml文件就运行。

模型设置接入异常

  • 原因：如果使用的是模型供应商中的 Minimax 等插件，这里大模型端口要求适配了 Anthropic 和 OpenAI 的标准，需要准备一致的标准。
  • 方案：调整适配端点。
    • 注意：插件配置Minimax的OpenAI的端点，不带上 v1 才是正确的

应用程序预览回复报错

  • 问题：预览加载一直弹出错误提示框

  • 原因：未调整（默认配置）模型。

  • 方案：调整模型；调整默认模型。

工作流下标溢出

  • 问题：下标访问溢出
  • 原因：开启了“文字转语音”功能，但又没有设置音色，又开启了自动播放，导致访问越界。可能跟版本有关系，目前可能还不支持相关的配置。
  • 方案：关闭“自动播放”功能项即可。

模型provider如何重新配置

  • 原因：插件模型存在一些选项不知道如何处理，遗漏或错误配置。

  • 方案：找到具体的模型，点击配置，并点击”编辑”的图标按钮。实际测试过，编辑保存后再打开也不对，最后只能选择删除再创建。

订阅并导入了Plan却没在Dify找到对应的模型

  • 原因：Dify 在模型 Provider 插件化设计上的强制类型隔离机制，决定了你导入AI Token Plan 的 API Key时能看到几十种model，但实际页面可使用的只有几种。
  • 方案：找到具体的页面，创建时自然会提示可用的模型；如果你依然不满意，也可以自行注册和提供 Provider，来满足你定制化的需要。

dify上embo-01模型向量化失败

  • 问题：使用了正确的key、minimax_group_id，但处理任何文件，都会报错404。
  • 原因：Dify的MiniMax插件支持了 OpenAI 和 Anthropic 两种标准，但如果 embedding 的接口使用的是 OpenAI 标准。
  • 方案：切换 Provider 的端点为 OpenAI 标准。
    • 注意：embedding 特别消耗 token 额度，建议一个一个文件来做，不然很快就让你的额度使用超标了。
