09 滑动窗口与双指针 ​

本质：把 O(n²) 的区间枚举压成一次扫描，关键是定义清楚循环不变量。 适合：连续子串或子数组的最长最短、两数之和的变体。

1. 场景 ​

输入是一个序列（字符串或数组），要的是某段连续区间的性质：最长不重复子串、覆盖全部字符的最短窗口、两端能围出的最大面积。

决定性条件藏在约束里：区间必须连续、n 大到 O(n²) 必超时、或者元素本身带结构（有序、可排序、值域有限）。任一条成立，就把 O(n²) 的枚举换成一次扫描。

认出信号：题面出现「连续子串」「最短窗口」「最长时间」「和为 K 的子数组」，而暴力枚举一遍是 O(n²)。这时先想窗口，别先想哈希——哈希解决的是「存在性」，窗口解决的是「连续性」。

2. 核心机制 ​

窗口 [left, right] 是当前候选区间：右指针负责扩大候选空间，左指针负责扔掉已经确定无用的部分。两个指针都只往前走，总步数不超过 2n，枚举区间就从 O(n²) 变成 O(n)。

左指针敢往前扔，依据是「某个信息一旦被扫过就永远不会再被需要」：0003 只要知道某字符上次出现在哪，就能定出左边界；0076 一旦凑齐 t 需要的字符，窗口左边的字符就已经多余。维护这个信息必须 O(1)，所以用「上次出现位置表」或「计数表」，而不是每次重新扫描窗口。

两种收缩语义要分清。0003 是「不合法就缩」：窗口必须始终无重复，所以左边界要跳到刚好让窗口合法的位置。0076 是「合法就缩」：窗口一合法就一路收缩，把更短的窗口记下来，缩到再缩就不合法为止。写反了要么漏掉更短的答案，要么退化成整个串。对撞双指针是同一套思想的镜像：两端往中间夹，每轮排除一整行或一整列的可能——0011 的排除依据是「短板决定容量」，0015 则先排序把「有序」变成可用信息，再夹逼找配对。

s = a b b a d
    0 1 2 3 4
        └─┘  ← 窗口 s[2:4] = "ba"，left=2 right=3

3. 套路清单 ​

套路做法复杂度备注
固定长度窗口右扩左缩，窗口长度恒为 k，每次移出旧元素、移入新元素再统计一次O(n) / O(1)移出与移入的顺序别反，否则统计量会短暂失衡
可变长度窗口（不合法就缩）右指针逐位推进，左指针只跳到「让窗口重新合法」的那一格O(n) / O(σ)记住「上一个重复位置」而不是逐格试探，否则退化 O(n²)
可变长度窗口（合法就缩）窗口一旦合法就记答案并收缩左边界，缩到不合法为止O(n) / O(σ)收缩的是更短的合法窗口，别写成「不合法才缩」
对撞双指针（移短板）首尾各一个指针，每轮只移动较短的那一侧O(n) / O(1)答案同时由高度与间距决定；数组不能先排序，下标就是间距
排序 + 对撞先排序把「有序」变成可用信息，再夹逼找配对O(n²) / O(1)排序只做一次；重复元素必须显式跳过

4.1 0003 Longest Substring Without Repeating Characters（Medium） ​

题目要点：给定字符串 s，求其中不含重复字符的最长子串长度；n 到 5×10^4，要求 O(n)。

教学实现

go
// lengthOfLongestSubstring 返回 s 中不含重复字符的最长子串长度。
func lengthOfLongestSubstring(s string) int {
	last := map[byte]int{}
	left, best := 0, 0
	for right := 0; right < len(s); right++ {
		c := s[right]
		// 只处理落在窗口内的重复：left 直接跳到重复字符的下一格，一格一格挪会退化成 O(n²)。
		if prev, ok := last[c]; ok && prev >= left {
			left = prev + 1
		}
		last[c] = right
		if w := right - left + 1; w > best {
			best = w
		}
	}
	return best
}

讲解：窗口的不变量是「[left, right] 内没有重复字符」，left 与 right 都只增不减，总步数因此是 O(n)。核心是 prev >= left 这个条件：只有重复字符落在当前窗口里才需要动 left，窗口外的旧重复直接忽略，否则 left 会被无谓推远、答案偏小。left 也不是一格一格挪，而是直接跳到 prev+1，因为 prev 到 left-1 之间的字符都被这个重复字符挡住，一次跳过去才不漏掉更长的窗口。边界不用特判：空串时循环不进入，best 保持 0；窗口长度是 right-left+1，闭区间两端都要算上。题目字符集是 ASCII，所以用 map[byte]int；换成定长数组常数还能再降一截，见第 7 节。

运行结果

text
0003 s="abcabcbb" -> 3
0003 s="bbbbb" -> 1
0003 s="" -> 0

4.2 0076 Minimum Window Substring（Hard） ​

题目要点：给定 s 和 t，求 s 中覆盖 t 全部字符（含重复）的最短子串；n 到 10^5，无解返回 ""。

教学实现

go
// minWindow 返回 s 中覆盖 t 全部字符（含重复）的最短窗口子串；无解返回 ""。
// counter[c] = 窗口内 c 的个数 - t 需要的 c 的个数：为负表示还缺。
func minWindow(s, t string) string {
	if len(t) == 0 || len(s) < len(t) {
		return ""
	}
	var counter [256]int
	for i := 0; i < len(t); i++ {
		counter[t[i]]--
	}
	missing, left := len(t), 0
	best := ""
	for right := 0; right < len(s); right++ {
		c := s[right]
		// 只在本来就缺时补缺口，否则 t 含重复字符时 missing 会被重复扣减。
		if counter[c] < 0 {
			missing--
		}
		counter[c]++
		for missing == 0 {
			if best == "" || right-left+1 < len(best) {
				best = s[left : right+1]
			}
			cl := s[left]
			counter[cl]--
			// 丢掉它就又缺了，收缩到此为止。
			if counter[cl] < 0 {
				missing++
			}
			left++
		}
	}
	return best
}

讲解：这题只维护一个数——「窗口还差几个字符」，而不是逐字符判断够不够。counter[c] 用一个数组同时记 need 与 have 的差：负数表示还缺，0 表示刚好够，正数表示多出来，于是 counter[c] < 0 一个判断就替代了两套数组的维护。右指针吃进字符时只有在它本来就缺的情况下才 missing--，这一步防的是 t 含重复字符时被重复扣减（t = "AAB" 遇到第二个 A 时 missing 会被扣成负数）。左指针的收缩语义是「合法就缩」：missing 归零就一路收缩，每收一格先更新答案，收缩到把某个字符丢掉又会缺为止才停——写成「不合法才缩」就永远退化成整个串。边界上 len(t) 大于 len(s) 或 t 为空直接返回 ""；没有任何窗口覆盖 t 时 best 始终是空串，同样返回 ""。

运行结果

text
0076 s="ADOBECODEBANC" t="ABC" -> "BANC"
0076 s="a" t="aa" -> ""
0076 s="abcabxyz" t="xyz" -> "xyz"

仓库实现：0076-minimum-window-substring/solution.go

4.3 0011 Container With Most Water（Medium） ​

题目要点：n 条垂线任选两条，与 x 轴围成容器，返回最大装水量；n 到 10^5。

教学实现

go
// maxArea 返回两条垂线与 x 轴围成的容器能装的最大水量。
func maxArea(height []int) int {
	left, right, best := 0, len(height)-1, 0
	for left < right {
		h := height[left]
		if height[right] < h {
			h = height[right]
		}
		if a := h * (right - left); a > best {
			best = a
		}
		// 移动短板：短板决定容量上限，移走长板只会让宽度变小。
		if height[left] < height[right] {
			left++
		} else {
			right--
		}
	}
	return best
}

讲解：面积由「短板高度」和「两线间距」共同决定。移动长板只会让间距变小、短板高度不变，容量不可能变大，所以长板这一侧的配对可以一次性排除。移动短板则相反：间距虽然变小，但 min 高度有可能变大，答案还有上升空间——因此每轮只移动较短的一侧不会漏掉最优解。注意公式里是 min 不是 max，写成 max 在 [1,8,6,2,5,4,8,3,7] 上就会直接算错。边界上 n 小于 2 时循环不进入、返回 0；高度为 0 的线参与计算也不报错，只是贡献面积为 0。这题千万别先排序：数组下标就是间距，排序会把位置信息全部丢掉。

运行结果

text
0011 height=[1 8 6 2 5 4 8 3 7] -> 49
0011 height=[1 1] -> 1
0011 height=[] -> 0

仓库实现：0011-container-with-most-water/solution.go

4.4 0015 3Sum（Medium） ​

题目要点：找出所有和为 0 且互不重复的三元组；n 到 3000，答案按任意顺序返回。

教学实现

go
// threeSum 返回所有和为 0 且互不重复的三元组。
func threeSum(nums []int) [][]int {
	a := append([]int(nil), nums...) // 排序会改原数组，先拷贝一份
	sort.Ints(a)
	res := [][]int{}
	for i := 0; i < len(a)-2; i++ {
		if a[i] > 0 {
			break // 剩下全是正数，凑不出 0
		}
		if i > 0 && a[i] == a[i-1] {
			continue
		}
		l, r := i+1, len(a)-1
		for l < r {
			sum := a[l] + a[r]
			switch {
			case sum == -a[i]:
				res = append(res, []int{a[i], a[l], a[r]})
				// 先跳过重复值再推进指针，顺序反了会跳掉刚露出来的新元素。
				for l < r && a[l] == a[l+1] {
					l++
				}
				for l < r && a[r] == a[r-1] {
					r--
				}
				l++
				r--
			case sum < -a[i]:
				l++
			default:
				r--
			}
		}
	}
	return res
}

讲解：排序把「任意两数之和」变成可以夹逼的形状：对撞指针比较 nums[l]+nums[r] 与目标 -nums[i]，和偏小就 l++（右移让和变大），和偏大就 r--，每轮排除一整行或一整列的可能，所以内层是 O(n)，外层再枚举 i，整体 O(n²)。去重要在三个地方各做一次：外层 i 跳过与前一个相同的值，内层命中后把 l 推过整段相同值、把 r 也推过整段相同值，少一处就会输出重复三元组。顺序也有讲究：先跳重复再 l++/r--，反了会跳掉刚露出来的新元素。a[i] > 0 时直接 break 是常数优化——剩下全是正数，凑不出 0。另外排序会改原数组，所以先拷贝一份再排。

运行结果

text
0015 nums=[-1 0 1 2 -1 -4] -> [[-1 -1 2] [-1 0 1]]
0015 nums=[0 1 1] -> []
0015 nums=[-2 0 1 1 2] -> [[-2 0 2] [-2 1 1]]

仓库实现：0015-3sum/solution.go

5. 变体与边界 ​

  1. 定长窗口（固定长度子串的最大和、异或和）：窗口长度固定，右扩时先把离开窗口的元素从统计里减掉，再把新元素加进来；统计结构可以是 sum、异或和或频次表。
  2. 「至多 K 个不同」转「恰好 K 个不同」：分别求至多 K-1 和至多 K 的窗口数，相减得到恰好 K；这类题必须先写至多版本。
  3. 要窗口内的最值而不是计数：换成单调队列，队列里存下标且保持对应的值单调递减，队首即当前窗口最值，复杂度仍是 O(n)。
  4. 排序前先问一句「下标是否参与答案」：0011 里下标就是间距，排序直接毁掉答案；0015 里下标不参与答案，排序反而是解法的第一步。

6. 常见错误 ​

  1. 只写「窗口不合法就缩」却没保证「缩到刚合法就停」：会把窗口缩过头，漏掉更短的合法窗口。改法：收缩写成 for missing == 0，合法期间一路收。
  2. 重复字符出现时把 left 只挪一格：应该直接跳到该字符上次出现位置的下一格，否则退化成 O(n²)。改法：left = prev + 1。
  3. 混淆「窗口内重复」与「历史上出现过」：0003 漏掉 prev >= left 这个条件，left 会被越推越远，最长长度算小。改法：只处理落在当前窗口内的重复。
  4. 面积公式用 max 而不是 min，或者移动长板而不是短板：前者把装水量算大，后者漏掉最优解。改法：面积取 min(height[left], height[right]) * (right-left)，每轮只移动较短的一侧。
