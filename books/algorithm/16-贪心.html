16 贪心 ​

每步取当前最优，靠证明把局部最优顶成全局最优。 适合：答案能一步步构造、区间互不重叠、排序后按序处理。

1. 场景 ​

这类题的形状很固定：给一组元素，要一个「最优」答案——最多能到哪、最少要几颗糖、最早切在哪——而且答案可以一段一段拼起来。

决定性的条件藏在约束里。0055 里 nums[i] 是「最多跳几格」，跳得越远不会吃亏；0134 里每个站的 gas[i] - cost[i] 有正有负，总和是唯一的生死线；0763 里字母只有 26 个，每个字母的最后一次出现位置直接决定段边界；0135 里只有相邻约束，没有全局约束。

信号是：题目要「最大值 / 最少数量」，而局部决策不会封死后面。看到这三点，先想贪心；想不出交换论证，就老实改 DP。

2. 核心机制 ​

贪心不是「随手挑一个看起来好的」，而是「挑一个能证明不更差的」。判据始终是同一条：当前这一步的选择，能被塞进某个最优解而不让它变差。本篇四道题覆盖四种证明形态。

0055 维护可达上界。 reach 是「已扫过的位置合起来最多能跳到哪」这个上确界，不是某条具体路径。它单调不减，一旦出现 i > reach，i 及其右边全部不可达，不必回头试别的跳法。

0134 总和够就一定有解。 令 d[i] = gas[i] - cost[i]，P 为其前缀和。P[n] < 0 则任何起点都缺油，无解。反之取 P 全局最小值的首次出现位置 m：从 m 出发，j > m 时余量 P[j] - P[m] ≥ 0，绕回前半圈时余量 P[n] - P[m] + P[j] ≥ P[n] ≥ 0，两段都不欠油。代码里「tank 变负就挪候选」做的正是追踪 P 的前缀最小值。

0763 最后一次出现位置决定段边界。 段内出现过 c 就必须盖到 last[c]，否则 c 被劈开；于是段尾至少是 max(last[c])，达到即合法。尽早切 → 后缀最长 → 后缀切出的段数不会更少 → 段数最多。

0135 左右需求取大。 left[i] / right[i] 分别是只顾左邻居、只顾右邻居时的最小糖果数；两条约束独立又必须同时成立，故取 max。逐位置贴着下界给，就是全局最小。

四题做法不同，骨架是同一个：每一步都在缩小「还剩多少可能」，而不是在候选方案里挑。贪心只保留一条路径并证明其余不必保留，DP 保留全部状态——这就是分界。失效信号是局部选择会清空后面的可行解；此时写不出交换论证，就改 DP。

3. 套路清单 ​

套路做法复杂度备注
可达性上界扫一遍维护 reach = max(reach, i+nums[i])，i > reach 即判死后面时间 O(n)，空间 O(1)只在「跳得更远不吃亏」时成立；求最少跳数要换成层数计数（0045）
总量守恒判定先算 Σ(收益-代价)，为负直接无解；再单趟扫出候选起点时间 O(n)，空间 O(1)必须先判总量，否则后面找的「候选」是假的
最早可行切点记每个键最后一次出现位置，段尾取 max(last[c])，能切立刻切时间 O(n)，空间 O(1)「尽早切」才最优；键值域要小（26 字母），否则用 map
双向取大左右各扫一遍得到两个下界，逐位置取 max时间 O(n)，空间 O(n)两条约束必须彼此独立；评分相等不算更高
排序贪心按某个键排序后按序处理，每次只取不冲突的那个时间 O(n log n)键选错就证不了：区间选择按右端点排序能证，按左端点不行
反悔贪心先按基线选，再回头修正已选过的（任务调度、合并区间）时间 O(n log n)用堆维护可以反悔的候选
贪心定序 + DP 定量贪心只决定处理顺序，数量与代价仍用 DP 算时间 O(n · 状态数)混合型；顺序一旦错，DP 的状态定义就跟着错

4.1 0055 Jump Game（Medium） ​

题目要点：给一个整数数组 nums，nums[i] 是从下标 i 出发最多能跳几格，问能否从下标 0 到达最后一个下标。

教学实现

go
// CanJump 判断从下标 0 出发能否到达最后一个下标。
func CanJump(nums []int) bool {
	reach := 0 // 已扫过的位置最多能跳到的下标
	for i, step := range nums {
		if i > reach {
			return false // i 够不到：能跳到 i 的位置都在它左边，而它们都跳不过 i
		}
		if i+step > reach {
			reach = i + step // 这一格把最远可达位置推到 i+step
		}
		if reach >= len(nums)-1 {
			return true // 已经够到末尾，后面的位置不必再扫
		}
	}
	return true
}

讲解：reach 是上界而不是路径——它记录「所有已扫过的位置合起来最多能跳到哪」，所以每到一个新位置只要用 i + nums[i] 把它顶上去，不必枚举从哪跳来。i > reach 是唯一的死局判据：能跳到 i 的位置必然都在 i 左边，而它们的最远落点不超过 reach，既然 reach < i，i 就没人跳得到，右边更没人跳得到。提前 return true（reach >= len(nums)-1）是纯优化，nums[0] 很大时直接结束；边界是空数组，约束里 n >= 1，代码对空数组返回 true。 一句话的正确性论证：reach 始终等于已访问位置能跳到的最远下标，故 i > reach 时 i 及其右侧全部不可达，扫描结束仍能覆盖末位即有解。

4.2 0134 Gas Station（Medium） ​

题目要点：环形路线上有 n 个站，第 i 站可以加 gas[i] 单位的油、到下一站要消耗 cost[i] 单位的油，问从哪个站出发能顺时针绕完一圈（无解返回 -1）。

教学实现

go
// CanCompleteCircuit 返回能绕行一圈的起点下标，无解返回 -1。
func CanCompleteCircuit(gas []int, cost []int) int {
	if len(gas) == 0 {
		return -1
	}
	total := 0
	for i := range gas {
		total += gas[i] - cost[i]
	}
	if total < 0 {
		return -1 // 总油不够总量，无论从哪出发都撑不完整圈
	}
	start, tank := 0, 0
	for i := range gas {
		tank += gas[i] - cost[i]
		if tank < 0 {
			start = i + 1 // 走到 i+1 已经欠油，[start..i] 整段都不能当起点
			tank = 0
		}
	}
	return start
}

讲解：第一步的 total < 0 不是优化而是前提——不管从哪出发，绕一圈的净收益恒等于 Σ(gas - cost)，为负就一定中途缺油。第二步的 tank < 0 → start = i+1 是全题核心：既然从 start 走到 i+1 已经欠油，区间 [start..i] 里任何位置出发只会更早欠油（起步油量更少），所以整段一起出局，候选直接跳到 i+1。tank = 0 是重置而非继续累加负值，因为候选换了人，之前的油量属于上一位候选。 一句话的正确性论证：候选始终是前缀和 P 最小值的首次出现位置，从该位置出发两段余量分别不低于 0 与 Σ(gas-cost) ≥ 0，故必有解。

运行结果

4.3 0763 Partition Labels（Medium） ​

题目要点：把一个字符串切成尽量多的段，要求同一个字母不出现在两个不同段里，返回各段长度。

教学实现

go
// PartitionLabels 把字符串切成尽量多的段，返回每段长度。
func PartitionLabels(s string) []int {
	var last [26]int // 每个字母最后一次出现的位置
	for i := 0; i < len(s); i++ {
		last[s[i]-'a'] = i
	}
	var sizes []int
	start, end := 0, 0
	for i := 0; i < len(s); i++ {
		if e := last[s[i]-'a']; e > end {
			end = e // 这一格要求当前段至少盖到它的最后一次出现
		}
		if i == end {
			sizes = append(sizes, end-start+1) // 段在这里闭合
			start = i + 1
		}
	}
	return sizes
}

讲解：last[26] 表先扫一遍建好，之后每个字符只做两件事——把段尾顶到 last[c]，再判断当前下标是否已经等于段尾。段尾取 max 是必须的：段里只要有 c，整段就得盖住 c 的最后一次出现，只盯着当前字符会把 c 劈成两半。i == end 才是合法切点，此时段内每个字符的最后一次出现都落在段内，一个字母不会跨段。切得越早，剩下的后缀越长，能切出的段数不会更少；last 表的键值域是 26，字母集换大就得换成 map。 一句话的正确性论证：任何合法划分的首刀都不能早于 max(last[c])，贪心取这个最早合法位置，留给后缀的空间最大，故段数最优。

4.4 0135 Candy（Hard） ​

题目要点：n 个孩子排成一列，每人一个评分，每人至少 1 颗糖，评分高于邻居的孩子必须比邻居多，返回最少糖数。

教学实现

go
// Candy 返回满足评分约束所需的最少糖果数。
func Candy(ratings []int) int {
	n := len(ratings)
	if n == 0 {
		return 0
	}
	left := make([]int, n) // 只满足左邻居约束时的最少糖果
	right := make([]int, n) // 只满足右邻居约束时的最少糖果
	for i := range left {
		left[i] = 1
	}
	for i := 1; i < n; i++ {
		if ratings[i] > ratings[i-1] {
			left[i] = left[i-1] + 1
		}
	}
	right[n-1] = 1
	for i := n - 2; i >= 0; i-- {
		right[i] = 1
		if ratings[i] > ratings[i+1] {
			right[i] = right[i+1] + 1
		}
	}
	total := 0
	for i := 0; i < n; i++ {
		if left[i] > right[i] {
			total += left[i] // 左右两个下限同时成立，取大的那个
		} else {
			total += right[i]
		}
	}
	return total
}

讲解：left 和 right 是两个独立的下限——left[i] 只用「评分比左邻居高」这一条约束推出来，right[i] 只用右边那一条。题目要求两条同时成立，所以 candy[i] 必须同时不低于两个下限，取 max 而不是相加。相等不算更高：ratings[i] > ratings[i-1] 里的严格大于不能写成 >=，否则评分全相等时会凭空多给糖。n == 1 要单独处理，两遍扫完后 left[0] = right[0] = 1，答案是 1 而不是 2。 一句话的正确性论证：逐位置取 max(left[i], right[i]) 恰好压住两条约束给出的下界，任何合法方案在该位置都不可能更小，故总和最小。

运行结果

0135 变体 ratings=[1 2 2] -> 4

5. 变体与边界 ​

  1. 同族换问法：0045 Jump Game II（Medium）问的是「最少跳几步」，reach 换成「层数边界」——同样维护最远可达位置，但每层结束才计数。
  2. 环形变体：0135 若孩子排成一圈（首尾也算邻居），用两趟 single-pass（分别假设 0 和 n-1 是峰）取较大值。
  3. 区间选择类：0452 Minimum Number of Arrows to Burst Balloons（Medium）、0435 Non-overlapping Intervals（Medium）都是「按右端点排序 + 取不冲突的那个」，证明结构与 0763 的「尽早切」同源。
  4. 分配类变体：0455 Assign Cookies（Easy）——两种口味都要满足时，先满足限制更严的那个（孩子胃口从小到大）。
  5. 贪心 + 堆：0871 Minimum Number of Refueling Stops（Hard）用堆维护「可以反悔」的候选；0621 Task Scheduler（Medium）直接用公式算冷却造成的空转。
  6. 二分套贪心：0410 Split Array Largest Sum（Hard）是「贪心划分 + 判定」，目标是「最小可行值」时用二分包一层。

6. 常见错误 ​

  1. 只给结论不给证明：写下「每步取最优所以全局最优」就收工，是本题型最大的坑；面试里必须补上交换论证或前缀和论证。
  2. 0134 忘了先判总和：总量不够时「候选起点」是假的，代码必须先算 Σ(gas-cost)，为负直接返回 -1。
  3. 0134 候选挪错了位置：tank 变负时挪到 i+1 而不是 i（挪 i 会在同一步再次欠油），重置 tank 时要置 0 而不是保留负值。
  4. 0763 只盯着当前字符：段尾必须取段内所有字符 last[c] 的最大值，只看当前字符会把某个字母劈成两半。
  5. 0135 左右相加而不是取大：max(left[i], right[i]) 是两个下限同时成立，不是两个数量要叠加；评分相等也不需要更多糖。
  6. 0055 把 reach 当成「我这一格能到的位置」：它必须是所有已访问位置的上界，写成单点跳法会漏掉「先跳到中间某点再跳更远」。
