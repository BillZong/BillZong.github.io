01 数组与字符串 ​

数组的所有技巧都建立在「下标就是状态」这一条上。 适合：输入是一维序列，要求统计、比较、变换或原地改写。

1. 场景 ​

输入是一维序列（数组，或按 rune 切开的字符串），输出往往还是同形状的序列：找一对配对元素、原地重排、逐位给出聚合值、整体平移。

约束里通常藏着决定性条件：值域是否落在 [0,n)、是否允许用除法、是否必须原地完成、是否必须保持相对顺序、k 是否可能大于数组长度。

认出这类题的信号是题面里的几个短语：in place、O(1) extra space、without using the division operator、maintaining the relative order。出现它们时，答案几乎一定是「一趟扫描 + 一份额外状态」，而不是排序或者建大哈希表。

2. 核心机制 ​

数组是一段连续内存，「第 i 个」这个位置本身就能当状态用。所有数组题都在做同一件事：把「第 i 个位置的结果」改写成「只依赖已经算好的前缀、后缀或已见集合」，于是可以从左到右一趟扫完，不用回头看。

结果依赖「我左边出现过哪些值」时，用哈希表记住已扫过的值，查找从 O(n) 降到 O(1)，这就是两数和。结果依赖「左右两段的聚合」时，先一趟写前缀，再一趟把后缀乘回去，两趟各带一个累加器，这就是乘积数组除自身以外。

要求原地重排且保序，就多维护一个写指针 w：扫描指针负责找值，w 负责回答「下一个该被填的位置」。w 只前进不后退，非零元素依次写进 nums[w]，写出的顺序天然就是原顺序。

要求整体平移时，把平移看成下标置换 i → (i+k) mod n。这个置换有三种实现：翻倍、三次反转、沿环搬。三次反转最省心，因为反转是自己的逆运算：整体反一次，再把前 k 段和后 n-k 段各反一次，循环右移就出来了。

nums        1    2    3    4    5
prefix      1    1    2    6   24
suffix        120   60   40   30   24

同一份「状态放在哪」的心法，套在四道题上就得到四种解法：值存在哈希表里（两数和）、存在答案数组里（乘积数组）、存在写指针里（移动零）、存在下标置换里（旋转数组）。

3. 套路清单 ​

套路做法复杂度备注
哈希表找配对遍历时先查 target-v 在不在表里，命中即返回下标，再把当前值连同下标写进表O(n) / O(n)顺序必须是先查后写，写反了会把同一个元素当成两个；不能建哈希表时改排序加双指针
原地重排（保序）用写指针 w 记下下一个非零该落的位，每个非零写进 nums[w] 并让 w 前移，扫完把 [w,n) 补零O(n) / O(1)w 只前进不后退，所以保序是白送的；不要求保序时可以改成交换法，少写一段补零
前缀积后缀积两趟扫描：先写左边的乘积，再从右往左把右边的乘积乘进同一个数组O(n) / O(1)题面禁除法时只能这么写；含 0、含负数都稳；把答案数组复用成前缀缓存可省一次分配
三次反转整段反转，再反转前 k 段，再反转后 n-k 段O(n) / O(1)先 k %= n；Go 的 % 对负数返回负值，归一化要写 ((k%n)+n)%n
环形置换沿 i → (i+k) mod n 的环把元素一路搬到目标位O(n) / O(1)gcd(n,k) 大于 1 时环不止一个，要从多个起点各走一遍
打标记找重复或缺失把下标当桶：nums[abs(v)]++，再扫一遍找空桶或计数超一的位置O(n) / O(1)要求值域在 [0,n) 且非负，否则得先归一化或退回哈希表
滑动窗口维护窗口内的字符计数，右端扩张、左端收缩到刚好合法O(n) / O(1)字符集固定用定长计数表；按 Unicode 切分要先转 []rune，额外 O(n) 空间

表里的复杂度统一是「时间 / 除输入外的额外空间」。

4. Go 实现 ​

4.1 0001 Two Sum（Easy） ​

题目要点：给一个整数数组和 target，返回两个不同下标使它们之和等于 target；题目保证有解，但同一个元素不能用两次。

教学实现

go
// TwoSum：在数组里找两个不同下标，使它们的和等于 target。
func TwoSum(nums []int, target int) []int {
	seen := make(map[int]int, len(nums)) // 值 -> 下标
	for i, v := range nums {
		// 先查配对再登记自己：顺序反了会把同一个元素当成两个
		if j, ok := seen[target-v]; ok {
			return []int{j, i}
		}
		seen[v] = i
	}
	return nil // 题面保证有解，这行只为让 go vet 通过
}

讲解：查表用 target-v 而不是 v，因为这一趟要回答的是「补数在不在我左边出现过」。先查后写这个顺序是本题唯一的坑：[3,3] 配 6 时如果先把 3 写进表，再查就会命中自己，返回 [0,0]。命中时返回的 [j, i] 里 j 一定小于 i，因为表里存的全是已经扫过的位置。空间是 O(n) 而不是 O(1)，换来的是时间从 O(n²) 降到 O(n)，这正是进阶提示要的。

运行结果

text
=== 0001 Two Sum ===
nums=[2 7 11 15] target=9 -> [0 1]
nums=[3 3] target=6 -> [0 1]
nums=[2 3] target=100 -> []

4.2 0283 Move Zeroes（Easy） ​

题目要点：把所有 0 挪到数组末尾，原地完成，且非零元素之间的相对顺序不能变。

教学实现

go
// MoveZeroes：把 0 全部挪到末尾，非零元素保持原有相对顺序。
func MoveZeroes(nums []int) {
	w := 0 // 下一个非零元素该落的位置
	for _, v := range nums {
		if v != 0 {
			nums[w] = v // 写指针只前进，写出的顺序就是原顺序
			w++
		}
	}
	for ; w < len(nums); w++ {
		nums[w] = 0 // 剩下的位置补零
	}
}

讲解：这里有两个指针，扫描指针只管找非零，写指针 w 只管「下一个空位在哪」。因为 w 从不后退，被搬走的元素必然落在它原来的相对次序上，保序是免费的。最后那段补零的循环不能省：写指针只是覆盖了前面的位置，尾部残留的还是旧值。另一种写法是拿非零元素去和前面的 0 交换，代价是要自己判断「交换的两个位置是不是同一个」，代码反而更长。

运行结果

text
=== 0283 Move Zeroes ===
[0 1 0 3 12] -> [1 3 12 0 0]
[0 0 1] -> [1 0 0]
[] -> []

仓库实现：0283-move-zeroes/solution.go

4.3 0238 Product of Array Except Self（Medium） ​

题目要点：返回数组 answer，answer[i] 等于除 nums[i] 外所有元素的乘积；必须 O(n)，且不许用除法。

教学实现

go
// ProductExceptSelf：ans[i] = 除 nums[i] 外所有元素的乘积，全程不用除法。
func ProductExceptSelf(nums []int) []int {
	ans := make([]int, len(nums))
	prefix := 1
	for i := range nums {
		ans[i] = prefix // 先记下左边全部的乘积
		prefix *= nums[i]
	}
	suffix := 1
	for i := len(nums) - 1; i >= 0; i-- {
		ans[i] *= suffix // 再乘上右边全部的乘积
		suffix *= nums[i]
	}
	return ans
}

讲解：把「除自己以外」拆成「左边的乘积 × 右边的乘积」，两趟各维护一个累加器就够。第一趟写前缀时，累加器要在写完之后再乘上当前元素，否则就把自己也乘进去了；第二趟同理，先乘再更新 suffix。两趟的顺序不能颠倒：前缀写完、后缀再乘，是唯一能复用同一个答案数组的走法，省掉一次 O(n) 分配。题面禁除法不是刁难，是为了让含 0 的输入也有确定答案——真用总和去除，遇到 0 就直接除零。

运行结果

text
=== 0238 Product of Array Except Self ===
[1 2 3 4] -> [24 12 8 6]
[-1 1 0 -3 3] -> [0 0 9 0 0]
[5] -> [1]

仓库实现：0238-product-of-array-except-self/solution.go

4.4 0189 Rotate Array（Medium） ​

题目要点：把数组原地右移 k 步，k 可以大于数组长度；要求 O(1) 额外空间。

教学实现

go
// Rotate：原地把数组右移 k 步。
func Rotate(nums []int, k int) {
	n := len(nums)
	if n == 0 {
		return // 否则下面 % n 会除零
	}
	k = ((k % n) + n) % n // Go 的 % 对负数返回负值，要归一化
	if k == 0 {
		return
	}
	reverseRange(nums, 0, n-1) // 整体反转
	reverseRange(nums, 0, k-1) // 前 k 个反转
	reverseRange(nums, k, n-1) // 后 n-k 个反转
}

func reverseRange(a []int, l, r int) {
	for l < r {
		a[l], a[r] = a[r], a[l]
		l++
		r--
	}
}

讲解：三次反转的顺序不能换。整体反转后，末尾 k 个元素跑到了最前面，但顺序是反的；把前 k 段再反一次就正回来了，剩下那段保持整体反转时的倒序，再反一次同样正回来，两段拼起来正好是「后 k 个 + 前 n-k 个」。k 必须先对 n 取模，否则切片下标会越界；归一化写成两遍取模，是因为 Go 的 % 遇到负数返回负值，别的语言一行就够。

运行结果

text
=== 0189 Rotate Array ===
[1 2 3 4 5 6 7] k=3 -> [5 6 7 1 2 3 4]
[-1 -100 3 99] k=2 -> [3 99 -1 -100]
[1 2 3] k=3 -> [1 2 3]

仓库实现：0189-rotate-array/solution.go

import "fmt"

// TwoSum：在数组里找两个不同下标，使它们的和等于 target。
func TwoSum(nums []int, target int) []int {

	return ans

	MoveZeroes(z1)

5. 变体与边界 ​

值域受限时的替代表达。当值域落在 [0,n) 且非负时，数组本身就是桶：把值 v 的出现次数记在 nums[v] 里，省掉哈希表。找重复数、找缺失数、原地计数排序都是这个套路。

保序要求会改变写法。移动零要求保序，写指针版本天然满足；改成交换法也能做，但要记住「先比较再交换」，否则会和自己交换，也容易在临时变量上覆盖掉还没读的值。

除法可用与不可用是两套解法。乘积类题目一旦允许除法并且保证无 0，一次求总和再逐个相除就是 O(n)；只要可能出现 0，或者题面直接禁除法，就必须回到前后缀乘积。

k 的取值范围。旋转题里 k 可能远大于 n，也可能为 0 或负数。取模、归一化、空数组提前返回，三件事缺一个就出错：n 为 0 时 % n 会直接 panic。

空输入与单元素。两数和无解时返回 nil；乘积数组输入为空时返回空切片；移动零和旋转对空数组都要安全返回。写测试时这些边界要单独列出来。

字符串版本。字符串是字节序列，按下标切分遇到非 ASCII 就会切坏。要按字符处理得先转 []rune，额外空间 O(n)，这一点和「O(1) 额外空间」的约束会打架，需要在题面允许的范围内取舍。

6. 常见错误 ​

两数和写成先写后查。[3,3] 配 6 时会返回 [0,0]，同一个元素被用了两次。改成先查 target-v、再把当前值写进表。

乘积题用总和去除。遇到 0 直接除零，含 0 的输入全错。改用前缀积加后缀积，顺便也避开了整除截断。

旋转题忘了取模。k 大于 n 时 nums[:k-1] 直接越界 panic；Go 的 % 对负数返回负值，还要写成 ((k%n)+n)%n。

前缀积和后缀积写反。先乘后写会把当前元素算进自己那一边，答案全错。固定顺序是「先写 ans[i]，再更新累加器」，两趟都如此。

写指针版本忘了补零。非零元素搬走了，尾部还留着旧值。把扫描结束后的 [w, n) 整段填 0。

交换写法里覆盖了还没读的值。手写临时变量时把两个值弄丢一个。Go 里直接 a[i], a[j] = a[j], a[i]，赋值是同时发生的，不会出现半途覆盖。
