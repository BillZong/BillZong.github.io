05 栈与队列 ​

栈只露一头，「最近来的」先处理，问题就能倒着问。 适合：括号匹配、找下一个更大元素、固定窗口最值。

1. 场景 ​

这类题的输入几乎总是一条线性序列——字符串、数组；输出也总是「每个位置一个答案」或「一个布尔值」。

决定性条件不在输入形状里，而在要求里：不是「求最值」，而是在扫描的同时，把刚刚过去的、还可能成为答案的候选留住。括号匹配的候选是「还没闭合的左括号」，下一个更大元素的候选是「还没等到更大值的下标」，滑动窗口最大值的候选是「还在窗口里的元素」。

认出信号有三句话：每个位置都要求答案；n 上限 10^5；回头扫一遍会超时。约束里决定语义而不是复杂度——0739 的「更暖」是严格大于，0239 的 k 固定，0084 的柱宽恒为 1。

2. 核心机制 ​

栈和队列的唯一区别是「从哪头取」：栈从栈顶（后进先出），队列从队首（先进先出）。共同点是只暴露一端——藏在里面的元素你看不见。这个限制恰恰是效率来源：一旦某个元素被压到另一端，它就再也等不到出场的机会，于是可以放心扔掉。

单调栈做的事是替未来的查询预判：新元素到来时，把栈里所有「被它永远压住」的元素一次性弹出，并顺手算出它们的答案。栈必须单调，是因为只有保持顺序，被弹出的元素才恰好是栈顶连续的一段——否则每来一个新元素都要整栈扫描，O(n) 退化成 O(n²)。

3. 套路清单 ​

套路做法复杂度备注
括号匹配左括号入栈（压入期望的右括号），右括号出栈比对，扫完栈必须空时间 O(n)，空间 O(n)多类型括号时计数法失效，必须记类型；空串算合法
单调栈求下一个更大/更小栈存下标，新元素到来时弹出所有比它小的栈顶，弹出即定答案时间 O(n)，空间 O(n)存下标才拿得到位置差；「更大」是严格大于
单调栈求矩形面积弹栈时高度取被弹柱子的高度，宽度取「新栈顶 + 1 .. i - 1」时间 O(n)，空间 O(n)末尾补 0 哨兵，否则单调递增输入会漏算
单调队列求窗口最值队尾弹出比新值小的，队首弹出过期的，队首即窗口最值时间 O(n)，空间 O(k)存下标才能判过期；要最小值就把队列改成递增
层序遍历队列按层推进，先记下 len(q) 再处理这一层时间 O(n)，空间 O(最宽层)不能边出队边计数，否则层边界会乱
最小栈辅助栈同步存当前最小值时间 O(n)，空间 O(n)用两个栈而不是一个栈加哨兵，push/pop 才都是 O(1)

4.1 0020 Valid Parentheses（Easy） ​

题目要点：判断只含 ()[]{} 的字符串是否为合法括号序列——同类型闭合、嵌套顺序正确、不能有落单的括号；长度上限 10^4。

教学实现

go
// IsValid 判断括号串是否合法：左括号入栈（压入期望的右括号），右括号出栈比对。
func IsValid(s string) bool {
	var stack []byte
	for i := 0; i < len(s); i++ {
		switch s[i] {
		case '(':
			stack = append(stack, ')')
		case '[':
			stack = append(stack, ']')
		case '{':
			stack = append(stack, '}')
		default:
			// 栈空说明没有可匹配的左括号；栈顶不符说明类型或嵌套顺序错了
			if len(stack) == 0 || stack[len(stack)-1] != s[i] {
				return false
			}
			stack = stack[:len(stack)-1]
		}
	}
	// 扫完必须正好清空：残留的左括号说明有没闭合的
	return len(stack) == 0
}

讲解

  • 压进栈的是「期望的右括号」而不是左括号本身：比对只需一次 ==，不必在比对时再做一次「左括号 → 右括号」的反查。
  • 取栈顶之前必须先判 len(stack) == 0，否则空栈上取 stack[len(stack)-1] 直接 panic。
  • 弹栈用重切片 stack = stack[:len(stack)-1]，Go 的 slice 重切片是 O(1)；包一个 pop 函数反而多一层调用开销。
  • 扫完必须 len(stack) == 0。只验「每个右括号都匹配」不够："(()" 的两个右括号都匹配得上，但左边还剩一个没闭合的左括号。

运行结果："()" → true、"([)]" → false、"" → true（完整 stdout 见 4.5）

仓库实现：0020-valid-parentheses/solution.go（含基准测试与性能数据，可回查完整工程化写法）

4.2 0739 Daily Temperatures（Medium） ​

题目要点：对每天求「还要等几天才会出现严格更暖的温度」，永远不会更暖的日子记 0；n 上限 10^5，温度值域 30–100。

教学实现

go
// DailyTemperatures 返回每天「还要等几天才会更暖」，永远不变暖的日子记 0。
func DailyTemperatures(temperatures []int) []int {
	answer := make([]int, len(temperatures))
	// 栈里放「还在等待更暖日子的下标」，对应温度从栈底到栈顶非递增
	var stack []int
	for i, t := range temperatures {
		for len(stack) > 0 && temperatures[stack[len(stack)-1]] < t {
			j := stack[len(stack)-1]
			stack = stack[:len(stack)-1]
			answer[j] = i - j // i 是 j 的第一个更暖日
		}
		stack = append(stack, i)
	}
	return answer
}

讲解

  • 栈里存下标而不是温度值：答案就是位置差 i - j，只存值就永远拿不到天数。
  • 弹栈条件是 temperatures[j] < t（严格小于），不是 <=。「更暖」要求严格大于，[70,70,71] 的正确答案是 [2,1,0]，写成 <= 会得到 [1,1,0]。
  • 为什么 i 一定是 j 的第一个更暖日：j 能留在栈里，说明它上面的每一天都不够暖；哪天够暖，j 早就被弹走了。
  • 代码里嵌套了 while，但摊还看的是「进出次数」：每个下标只入栈一次、出栈至多一次，总操作数仍是 O(n)。

运行结果：[73 74 75 71 69 72 76 73] → [1 1 4 2 1 1 0 0]、[70 70 71] → [2 1 0]、[100] → [0]（完整 stdout 见 4.5）

仓库实现：0739-daily-temperatures/solution.go

4.3 0084 Largest Rectangle in Histogram（Hard） ​

题目要点：在柱状图里求轴对齐的最大矩形，柱宽恒为 1；n 上限 10^5，柱高 0–10^4。

教学实现

go
// LargestRectangleArea 求柱状图中的最大矩形面积。
func LargestRectangleArea(heights []int) int {
	// 末尾补一根高度 0 的哨兵，保证单调递增的输入也能把栈排空
	h := append(append([]int{}, heights...), 0)
	stack := make([]int, 0, len(h)) // 下标，对应高度非递减
	best := 0
	for i := 0; i < len(h); i++ {
		for len(stack) > 0 && h[stack[len(stack)-1]] > h[i] {
			top := stack[len(stack)-1]
			stack = stack[:len(stack)-1]
			// 宽度：从新栈顶 + 1 到 i - 1；栈空说明能一路扩到下标 0
			width := i
			if len(stack) > 0 {
				width = i - stack[len(stack)-1] - 1
			}
			if area := h[top] * width; area > best {
				best = area
			}
		}
		stack = append(stack, i)
	}
	return best
}

讲解

  • 关键观察：最优矩形一定以某根柱子为最矮边，所以只需枚举「以每根柱子为最矮边时的最大宽度」。
  • 栈里存下标，对应高度非递增。遇到比栈顶矮的柱子 i 时，栈顶 top 的高度就是限高：左边被新栈顶卡住、右边被 i 卡住，宽度是 i - 新栈顶 - 1。
  • 栈空时宽度直接是 i（能一路扩到下标 0），漏掉这个分支面积会算小。
  • 末尾补一根高度 0 的哨兵把栈强制排空：没有它，单调递增的 [1,2,3,4,5] 最后一根永远不弹，会少算面积 9。补哨兵用拷贝而不是 append(heights, 0)，后者会写进调用方的底层数组。

运行结果：[2 1 5 6 2 3] → 10、[5 5 5 5] → 20、[] → 0（完整 stdout 见 4.5）

仓库实现：0084-largest-rectangle-in-histogram/solution.go

4.4 0239 Sliding Window Maximum（Hard） ​

题目要点：给定数组与固定窗口大小 k，输出每个长度为 k 的窗口的最大值；n 上限 10^5，1 ≤ k ≤ n。

教学实现

go
// MaxSlidingWindow 返回每个长度为 k 的窗口的最大值。
func MaxSlidingWindow(nums []int, k int) []int {
	if len(nums) == 0 || k <= 0 {
		return nil
	}
	deque := make([]int, 0, k) // 存下标，对应值从队首到队尾单调递减
	out := make([]int, 0, len(nums)-k+1)
	for i, v := range nums {
		// 队尾比 v 小或相等的旧下标被 v 压住，再也当不上窗口最大值
		for len(deque) > 0 && nums[deque[len(deque)-1]] <= v {
			deque = deque[:len(deque)-1]
		}
		deque = append(deque, i)
		// 队首过期（已滑出窗口）
		if deque[0] <= i-k {
			deque = deque[1:]
		}
		if i >= k-1 {
			out = append(out, nums[deque[0]]) // 队首恒为当前窗口最大值
		}
	}
	return out
}

讲解

  • 队列里存下标：既要比值判断谁被压住，又要靠下标判断谁过期（deque[0] <= i-k）。存值就做不了后者。
  • 队尾弹出所有 <= v 的旧下标：它们被新元素压住，只要新元素还在窗口里就不可能再当最大值。
  • 队首恒为当前窗口最大值：比它小的都被压掉了，比它大的也早已被更靠右的更大元素压掉，剩下的它最大。
  • 只有 i >= k-1（窗口凑满）时才记一次，输出长度正好是 n-k+1；空间是 O(k) 而不是 O(n)，队列里的下标始终落在当前窗口内。

运行结果：[1 3 -1 -3 5 3 6 7] k=3 → [3 3 5 5 6 7]、[1 2 3 4 5] k=2 → [2 3 4 5]、[] k=3 → []（完整 stdout 见 4.5）

仓库实现：0239-sliding-window-maximum/solution.go

5. 变体与边界 ​

  1. 下一个更大/更小元素（0496 / 0503）：0739 换掉比较方向就是模板。要多改的是「答案存什么」——0496 存数值、0503 存下标且数组是循环的，末尾要绕回开头再扫一遍。
  2. 滑动窗口最小值 / 同时要 min 和 max：要多改的是方向——最小值用递增队列；同时维护就并行跑两条方向相反的单调队列，各管一头。
  3. 窗口大小可变的最值：要多改的是过期条件——从固定的 i-k 换成业务推进的 i-left，left 按约束（如窗口和不超过 S）滑动。
  4. 接雨水（0042）：用的还是单调栈。要多改的是「栈里存什么的语义」——存的是还没填坑的墙的对，答案按 (坑底高度 - 墙高) × 宽度算，而不是高度 × 宽度。
  5. 括号匹配的最少删除版本：要多改的是「不匹配时怎么办」——给每种括号配一个计数器，扫完剩下的总数就是要删的数量，多类型时仍需要栈来判嵌套顺序。

6. 常见错误 ​

  1. 0739 弹栈条件写成 <= → 相等温度被当成「更暖」，[70,70,71] 输出 [1,1,0] 而不是 [2,1,0]。改法：统一用严格小于。
  2. 0084 不补哨兵 → 单调递增的输入最后一根柱子永远不弹栈，少算一块面积。改法：末尾补一根高度 0 的柱子。
  3. 0084 宽度忘了「栈空」分支 → 栈空时宽度是 i 而不是 i-stack[top]-1，面积算小。改法：宽度先默认取 i，栈非空再覆盖。
  4. 0020 只验「每个右括号都匹配」 → 忘了扫完栈必须空，"(()" 这类会漏判。改法：末尾加 len(stack) == 0。
  5. 栈/队列里存值而不是下标 → 0739 拿不到天数、0084 拿不到宽度、0239 判不了过期。改法：一律存下标，值通过 nums[j] 现场取。
