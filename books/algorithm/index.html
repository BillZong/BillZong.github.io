算法体系文章系列 · 阅读指南 ​

这一系列是 1761 道刷题记录的细节手册。每篇文章对应一个算法主题，把「这类题长什么样、为什么能这么想、边界在哪、Go 怎么写」讲透。

配套的速查地图是算法体系总结-20261025.md（21 个主题的全景脑图 + 套路清单 + 选型速查表）。用法是：先用汇总稿定位主题，再进对应文章看细节。

1. 先看哪几篇 ​

如果你是第一次系统过一遍，按这个顺序读，依赖关系最顺：

顺序文章为什么放这个位置
101 数组与字符串所有题目的载体，后面每一篇都建立在它上面
202 哈希表与计数最常用的加速手段，map 的语义要一次讲清
305 栈与队列单调栈 / 单调队列是后面多个主题的公共零件
408 二分查找「答案单调」这个思维方式比代码本身重要
509 滑动窗口与双指针把 O(n²) 压成 O(n) 的两种典型形态
612 深度优先搜索回溯、连通块、拓扑都从这里长出来
713 广度优先搜索与 DFS 构成图论的两只基本手
818 动态规划最需要状态设计的一类，单独留足篇幅

其余 13 篇按需翻：遇到什么题就回到对应主题，不必按顺序读。

2. 21 篇一览 ​

「什么时候翻」这一列是题面信号，看到就跳过去。

#文章什么时候翻
01数组与字符串输入是一维序列；要统计、比较、变换某个连续段；要求原地改
02哈希表与计数要判重复、统计频次、记录「上次出现位置」；要 O(1) 判存在
03排序要第 K 大/小；要按位次处理；要「排序后相邻配对」；要自定义比较规则
04链表题面给 head / 节点结构；要反转、断链、合并；出现「倒数第 k 个」「找环」「找交点」
05栈与队列括号匹配、表达式求值、单调性维护、层序遍历、固定窗口最值
06字典树大量字符串且查询以字符串前缀出现；统计以某串开头的数量；自动补全
07堆Top K、第 K 大/小、流式最值、多路归并、任务调度
08二分查找答案空间是整数区间；要求最小/最大值满足某条件；有序数组找边界
09滑动窗口与双指针连续子数组/子串的最长最短；要「窗口内不重复/不超限」；两数之和的变体
10前缀和问连续区间的和或和的某个性质；「和为 K 的子数组」；二维矩形区域和
11递归与分治题面有「在区间里选」「合并两个有序序列」「求中位数」；要把 O(n²) 降到 O(n log n)
12深度优先搜索连通块计数；枚举所有可能方案；路径搜索；依赖关系判环
13广度优先搜索求最短步数/最短距离；按层输出；状态空间是一张隐式图
14树题面给二叉树 / BST；求路径和、深度、直径、LCA；要序列化
15图题面给边集或邻接表；求路径/顺序/连通分量；判断有无环
16贪心求最大值/最小值且答案能逐步构造；区间选择类；排序后按序处理
17位运算与数学出现「只出现一次」「子集」「异或」「每个元素出现 k 次」；涉及整除、余数、进制、约数、质数
18动态规划求最优解或计数；存在重叠子问题；有「无后效性」
19设计类要你实现一个类，含 add/remove/query 等多个操作，且有性能要求
20模拟描述一堆操作问某个时刻的状态；「实现一个……类/方法」但没有性能要求
21数据库与 SQL给表结构和查询要求，返回一张表

3. 每篇文章的结构 ​

七节固定，方便你按需跳读：

text
1. 场景        这类题长什么样，约束里藏着什么决定性条件
2. 核心机制    为什么这类题能被这个方法解（推导，不是结论）
3. 套路清单    可直接抄的招式表：做法 / 复杂度 / 前提与坑
4. Go 实现     逐题：题目要点 → 教学实现 → 讲解 → 真实运行结果
5. 变体与边界  同一手法的其他题型，差在哪一处
6. 常见错误    实战真会踩的坑
7. 延伸        相关题号 + 仓库路径 + 汇总稿对应小节

想快速过一遍就只看 3 套路清单 和 6 常见错误；想真正吃透就看 2 核心机制 和 4 Go 实现。

输出块的两种排版：4.1–4.x 每小节各自带一个 text 块（多数篇目如此）；05 栈与队列、06 字典树两篇为了控制篇幅，把每小节的结果压成一行内联摘要，完整 stdout 统一放在该篇末尾的「完整可运行示例」里。信息量相同，只是摆放位置不同。

4. 本系列的三条约定 ​

一、Go 示例是重写的精简教学版，不是仓库代码的复制。 仓库 leetcode-answers 里每道题都有工程化的完整实现（含基准测试、性能基线、复杂度分析）。文章里的代码是另写的一份精简版：只保留教学点，注释只解释「为什么」。两者行为必须一致——每篇文章的示例都在临时模块里跟仓库真实实现做过差分对拍（固定边界用例 + 固定种子的随机用例），差异必须为空。需要看完整工程化写法时，文章里给了仓库路径。

二、「运行结果」是实测输出。 每篇文章末尾的 text 代码块是程序真实跑出来的 stdout，逐字复制，不是手写的示意。示例至少覆盖 3 组输入：题面示例 + 2 组边界或变体（空输入 / 单元素 / 重复 / 全同 / 极值），输出能直接看出边界是怎么处理的。

三、题号、题名、难度与仓库逐字对齐。 文中出现的每个题号都在 leetcode-answers 仓库里有真实目录，题名与难度取自该题的 README。仓库里某题没收录更优解时，延伸清单会明说「未收录」，不硬凑。

5. 与汇总稿的关系 ​

算法体系总结-20261025.md（汇总稿）本系列
定位速查地图细节手册
形态每主题 5 段 + 4 张全景脑图每主题 7 段 + 逐题 Go 教学实现
什么时候用拿到新题，先定位主题定位到主题后，看清机制与边界
篇幅约 930 行每篇 200–400 行，共 21 篇

两边的结论一致。个别地方文章里的写法更简洁（例如教学版代码可能用更短的写法），细节以文章为准，汇总稿负责导航。

6. 仓库对照 ​

text
leetcode-answers/
├── <题号>-<slug>/
│   ├── README.md              # 官方题面原文（示例与约束）
│   ├── NOTE.md                # 实际采用的解法 + 性能基线 + 卡点
│   ├── solution.go            # 工程化实现（部分题是 solution.sql）
│   ├── solution_test.go       # 单测（期望值由暴力解或独立实现推导）
│   └── other-best-answers/    # 收录的公开更优解

文章里提到某个题号时，对应目录就是上面这个结构；4. Go 实现 小节末尾的「仓库实现」一行给的就是相对路径。
