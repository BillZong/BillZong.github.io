10 前缀和 ​

区间和 = 两个前缀和相减，前缀把「区间」压成「两个点」。 适合：区间求和、和为 K 的子数组、二维矩形和。

1. 场景 ​

输入是一串数字，提问却只关心其中某一段：这段的总和是多少？有多少段的总和等于某个值？

决定性条件藏在约束里：0303 的数组构造后不再变，可以提前算好；0308 的数组会被反复改；0560 的数组含负数；0525 的数组只有 0 和 1。

信号是「问连续区间的和」或「问两段和的关系」。一旦看见「区间」，先想前缀和，而不是真的去累加每一段。

2. 核心机制 ​

前缀和 pre[i] 是前 i 个元素之和，pre[0] = 0。于是 nums[l..r] 的和 = pre[r+1] - pre[l]：两个前缀一减，中间的区间就消失了。拿 [-2, 0, 3, -5, 2] 试一下：nums[1..3] 的和 = pre[4] - pre[1] = -4 - (-2) = -2，正好等于 0 + 3 - 5。

下标       0     1     2     3     4
a[]       -2     0     3    -5     2
pre[]      0    -2    -2     1    -4      pre[i+1] = pre[i] + a[i]

不要求「区间和」而是问「多少个区间的和是 k」时，就把两个前缀和做差：cum[j] - cum[l] = k 意味着 cum[l] = cum[j] - k。于是用 map 记每个前缀和出现过几次，扫到 cum 时答案加上 count[cum-k]——这是 0560。

0525 是同一招换了个编码：0 当 -1、1 当 +1，「0 和 1 一样多」就变成「这段和为 0」，也变成「两个前缀和相等」。map 改记每个前缀和最早出现的位置，位置差就是区间长度。

二维照抄：pre[i][j] 存左上角矩形和，矩形和用四项容斥。但改一个格子 (r,c)，它右下方的 (m-r)(n-c) 个前缀项全部作废——查询 O(1) 的代价是更新 O(mn)。这就是 0308 的核心矛盾：想让查询快，就得接受更新贵；两头都想快，只能换结构，比如二维树状数组。

3. 套路清单 ​

套路做法复杂度备注
一维前缀和（静态）构造时算 pre[i+1] = pre[i] + a[i]，查询取 pre[r+1] - pre[l]建 O(n) / 查 O(1)，空间 O(n)数组不变才划算；pre 长度必须是 n+1，右端点要 +1
前缀和作键map[sum] 存出现次数，扫到 cum 时答案加 count[cum-k]时间 O(n)，空间 O(n)数组含负数也成立；频次表不依赖单调性
恰好 K 与至多 K「恰好 K」=「至多 K」减「至多 K-1」，后者用滑动窗口时间 O(n)，空间 O(1)滑动窗口要求元素非负；含负数只能走频次表
前缀和 + 最早位置map[sum] 记最早下标，同前缀和的位置差就是候选区间长时间 O(n)，空间 O(n)只记最早；记最晚会把答案缩短
二维前缀和建 pre[i][j]，矩形和 = 四项容斥建 O(mn) / 查 O(1)，空间 O(mn)改一格污染 (m-r)(n-c) 项，更新必然 O(mn)
二维可变二维树状数组或二维线段树，更新与查询都走对数步每次 O(log m · log n)，空间 O(mn)放弃 O(1) 查询，换更新的可控代价

四道题共用一条主线：把区间压缩成两个前缀。4.1–4.4 贴的是片段实现，4.5 是可以直接 go run 的完整程序。

4.1 0560 Subarray Sum Equals K（Medium） ​

题目要点：给一个整数数组和 k，返回和恰好为 k 的连续子数组个数（数组可以含负数）。

教学实现

go
// SubarraySum 返回和恰好为 k 的连续子数组个数。
func SubarraySum(nums []int, k int) int {
	count := map[int]int{0: 1} // 空前缀先记账，否则漏掉"从下标 0 开始"的子数组
	cum, ans := 0, 0
	for _, v := range nums {
		cum += v
		ans += count[cum-k] // 以当前元素结尾、和为 k 的子数组个数
		count[cum]++
	}
	return ans
}

讲解：count[0] = 1 代表「左端点可以取在下标 0」，少了这行，所有从开头开始的子数组都会漏算。累加必须写在记账前面：k = 0 时当前前缀自己就是候选，顺序反了会少算。键是前缀和、值是出现次数——要的是「个数」而不是「位置」，所以这里存频次。数组含负数时不能用滑动窗口（窗口和不再单调），频次表对正负完全不敏感。另外「恰好 K」和「至多 K」是两回事，后者能靠滑动窗口减法做，前提是元素非负。

4.2 0303 Range Sum Query - Immutable（Easy） ​

题目要点：数组在构造后不再变化，要反复回答「nums[left..right] 的和是多少」（左右都含）。

教学实现

go
// NumArray 预存前缀和，把区间和查询变成两次数组访问。
type NumArray struct {
	prefix []int
}

// NewNumArray 构造时一次性算好长度 n+1 的前缀和表。
func NewNumArray(nums []int) *NumArray {
	prefix := make([]int, len(nums)+1)
	for i, v := range nums {
		prefix[i+1] = prefix[i] + v
	}
	return &NumArray{prefix: prefix}
}

// SumRange 返回 nums[left..right] 的和，左右都含。
func (n *NumArray) SumRange(left, right int) int {
	return n.prefix[right+1] - n.prefix[left]
}

讲解：prefix 长度是 n+1 而不是 n，pre[0] = 0 是哨兵，这样 left = 0 时不用再写一个 if。查询写 pre[right+1] - pre[left]，右端点的 +1 来自「pre[i] 存的是前 i 个元素之和」这个约定，少一次 +1 就整体差一位。构造 O(n)、查询 O(1)，用 O(n) 空间把每次查询的 O(n) 累加换掉；查询次数远多于数组长度时这笔买卖才划算。这一切的前提是「数组不变」——一旦允许修改，O(1) 查询的代价就从更新那边还回来，这是 4.4 要讲的矛盾。

4.3 0525 Contiguous Array（Medium） ​

题目要点：给一个只含 0 和 1 的数组，返回 0 与 1 数量相同的最长连续子数组长度。

教学实现

go
// FindMaxLength 返回 0 与 1 数量相同的最长连续子数组长度。
func FindMaxLength(nums []int) int {
	first := map[int]int{0: -1} // 前缀和 -> 最早出现的位置
	sum, best := 0, 0
	for i, v := range nums {
		if v == 0 {
			sum--
		} else {
			sum++
		}
		j, ok := first[sum]
		if !ok {
			first[sum] = i // 只记最早位置：后记的位置只会让区间更短
			continue
		}
		if i-j > best {
			best = i - j
		}
	}
	return best
}

讲解：把 0 映射成 -1、1 映射成 +1，「0 和 1 一样多」就等价于「这段的和是 0」，也就等价于「区间两端的前缀和相等」。map 里记的是最早出现的位置：同一个前缀和出现两次，位置差就是中间区间的长度，起点越早区间越长，记最晚只会得到更短的答案。first[0] = -1 是哨兵，对应「空前缀在下标 -1」，这样从下标 0 开始的平衡区间才算得到长度。值域只有 [-n, n]，也可以用数组加偏移替掉 map；n 到 10^5 时 map 完全够用。

4.4 0308 Range Sum Query 2D - Mutable（Hard） ​

题目要点：给一个 m×n 矩阵，要同时支持单点赋值和矩形区域求和，两种操作各最多 10^4 次。

教学实现

go
// NumMatrix 用「二维前缀和 + 四项容斥」回答矩形和。
type NumMatrix struct {
	raw [][]int // 原矩阵：重建前缀和表时要用
	pre [][]int // 前缀和表：pre[i][j] 是 raw[0..i-1][0..j-1] 的和
}

// NewNumMatrix 构造时建好 (m+1)x(n+1) 的前缀和表。
func NewNumMatrix(matrix [][]int) *NumMatrix {
	m, n := len(matrix), len(matrix[0])
	nm := &NumMatrix{raw: make([][]int, m), pre: make([][]int, m+1)}
	for i := range nm.pre {
		nm.pre[i] = make([]int, n+1)
	}
	for r := 0; r < m; r++ {
		nm.raw[r] = make([]int, n)
		for c := 0; c < n; c++ {
			nm.raw[r][c] = matrix[r][c]
			nm.pre[r+1][c+1] = matrix[r][c] + nm.pre[r][c+1] + nm.pre[r+1][c] - nm.pre[r][c]
		}
	}
	return nm
}

// Update 赋值后旧的前缀和表全部作废，只能重建。
func (nm *NumMatrix) Update(row, col, val int) {
	nm.raw[row][col] = val
	for r := 0; r < len(nm.raw); r++ {
		for c := 0; c < len(nm.raw[r]); c++ {
			nm.pre[r+1][c+1] = nm.raw[r][c] + nm.pre[r][c+1] + nm.pre[r+1][c] - nm.pre[r][c]
		}
	}
}

// SumRegion 用四项容斥求矩形 [row1..row2] x [col1..col2] 的和。
func (nm *NumMatrix) SumRegion(row1, col1, row2, col2 int) int {
	return nm.pre[row2+1][col2+1] - nm.pre[row1][col2+1] -
		nm.pre[row2+1][col1] + nm.pre[row1][col1]
}

讲解：二维前缀和 pre[i][j] 加四项容斥能让矩形查询是 O(1)，这是 0304 的做法；但改一个格子 (r,c)，它右下方的 (m-r)(n-c) 个前缀项全部作废，所以「查询 O(1)」必然换来「更新 O(mn)」——省下的时间会从更新那边还回去，这正是本文最核心的矛盾。教学版选了重建这条便宜的路线：赋值之后整张表重算一遍，于是它的时间账是「更新 O(mn) + 查询 O(1)」。仓库版换成二维树状数组，改一格只沿两个维度各跳对数步，更新与查询都是 O(log m · log n)，等于放弃 O(1) 查询换掉 O(mn) 更新。raw 只是影子矩阵，用来把「赋值」翻译成「增量」，真正干活的是 pre 表；选哪条路要看更新与查询的比例。

5. 变体与边界 ​

  1. 二维不可变：0304 用 pre[i][j] + 四项容斥，查询 O(1)；0308 只是把「数组不变」这个前提拿掉了，其余推导完全一样。
  2. 「恰好 K」的另一条路：元素全非负时，「至多 K」可以用滑动窗口 O(n) O(1) 算出来，再由「恰好 K = 至多 K − 至多 K−1」得到 0209 家族的做法；0560 有负数，只能走频次表。
  3. 计数而非最值：0930 Binary Subarrays With Sum（Medium）与 0560 同构，数组限定成 0/1，问「和为 goal 的子数组个数」；1004 Max Consecutive Ones III（Medium）问的是「最多翻 k 个 0 之后的最长连续 1 段」，是滑动窗口版本。
  4. 前缀积与前缀异或：前缀积要单独统计含 0 的段（0 会把乘积清零，后面没法再除）；前缀异或则是 pre[i] ^ pre[j]，但异或没有先后顺序，像和那样「相减」是不成立的。
  5. 最短而非最长：0862 Shortest Subarray with Sum at Least K 里前缀和是无序的，要配单调栈，不能像 0525 那样只记一个最早位置。

6. 常见错误 ​

  1. 0560 的两处顺序：count[0] = 1 不能少（空前缀代表左端点取下标 0，少了它所有「从开头开始」的子数组都会漏算）；累加也必须写在记账前面（k = 0 时当前前缀自己就是候选，顺序反了会少算）。
  2. pre 表的下标约定不统一：统一用长度 n+1、pre[0] = 0，查询写 pre[right+1] - pre[left]；少一次 +1 就整体差一位。
  3. 0525 记了最晚的位置：同一个前缀和要记最早出现的位置，记最晚会让区间变短，答案偏小。
  4. 拿滑动窗口去解 0560：数组含负数时窗口和不再单调，「不合法就缩」的依据整个失效。
  5. 以为二维前缀和能同时拿到 O(1) 查询和 O(1) 更新：改一格必然要重建（0308 教学版）或改用树状数组（仓库版），没有第三条路。
