18 动态规划 ​

把「答案依赖什么」写成状态，DP 的全部难度都在这里。 适合：求最优解或计数，且子问题重叠、无后效性。

1. 场景 ​

输入是一串数、一棵树或一堆石子，输出通常只是一个数。决定解法的不是规模，而是「答案依赖什么」能不能写成一张有限的表。约束里藏着信号：「n ≤ 45」说明状态只有一维；「每种硬币数量无限」说明是完全背包；「二叉树、相邻节点不能同时偷」说明状态要挂在树上；「n ≤ 16」说明 2^n 的子集枚举还付得起。

认出这类题要同时看到三个信号：① 求最优解或方案数；② 不同的输入反复问到同一个子问题（重叠子问题）；③ 当前决策不影响后续能做的选择（无后效性）。

第三条最关键——只要「做完这一步之后世界变了，但变化的规律是确定的」，答案就能写成状态的函数。

2. 核心机制 ​

DP 只有一个动作：把「答案依赖什么」写成状态。状态定下来，转移、初始值、答案位置三样就都定了；状态定错，转移写得再漂亮也没用。

合格的状态要同时满足两点：给定状态答案唯一（不多），且只含后面真正用得到的信息（不少）。0070 的状态是「还差几级」，因为下一步只需要知道这个；1140 的状态必须带上 m，因为上一手取了几堆直接决定这一手能取几堆。

另一个反复出现的细节是初始值不等于默认值。0322 的 dp[0] = 0 表示「凑 0 元要 0 枚」，其余格子先填不可达；1140 的记忆化哨兵必须是 -1 而不是 0，因为 0 本身是合法答案（对手一把拿完时我就拿 0），拿它当「未计算」会让真实答案被误判成缓存命中。

3. 套路清单 ​

套路做法复杂度备注
线性 DPf[i] = f[i-1] + f[i-2]，只留前两项时间 O(n)，空间 O(1)f[0] = 1（原地不动也算一种走法），写成 0 递推会断
最大子段和维护「以当前元素结尾的最大和」，与「从当前元素重新开始」取大时间 O(n)，空间 O(1)初始值取 nums[0]，取 0 会让全负数组返回 0（题目要非空）
完全背包硬币在外层、容量在内层正序遍历时间 O(amount×|coins|)，空间 O(amount)容量倒序就退化成 0/1 背包，每种硬币只能用一次
树形 DPdfs(node) 返回「父节点需要的两种情形的最优值」时间 O(n)，空间 O(h)必须返回两个值（取 / 不取），只返回一个会丢信息
回溯 + 剪枝降序排序 + 同和桶去重 + 空桶失败 break最坏 O(k^n)，剪枝后接近 O(2^n)前提是 n ≤ 16；n > 20 连位掩码都压不动
博弈 DPf(i,m) = 总量 − min(对手在该状态的结果)时间 O(n^3)，空间 O(n^2)「自己 = 总量 − 对手」只在零和博弈里成立；哨兵不能用 0

4. Go 实现 ​

六题覆盖线性 DP、完全背包、树形 DP、回溯剪枝、博弈 DP 五种摆法。每题先说清「状态是什么、转移为什么这么写、初始值与答案在哪」，再给教学实现；4.7 是把它们拼起来的完整程序。

4.1 0070 Climbing Stairs（Easy） ​

题目要点：爬到第 n 级台阶，每次迈 1 级或 2 级，问共有多少种走法。 教学实现

go
// ClimbStairs 返回爬到第 n 级台阶的方案数：f[i] = f[i-1] + f[i-2]，f[0] = f[1] = 1。
func ClimbStairs(n int) int {
	prev, cur := 1, 1 // f[0], f[1]
	for i := 2; i <= n; i++ {
		prev, cur = cur, prev+cur
	}
	return cur
}

讲解：状态 f[i] 是「走完前 i 级的方案数」，转移 f[i] = f[i-1] + f[i-2] 按「最后一步迈 1 级还是 2 级」分类，两个子类互斥且穷尽，所以可以直接相加。初始值 f[0] = 1 是这里唯一的坑：空路径也算一种走法，写成 0 会让递推从 f[1] 就开始断档（n=2 会算成 1）。答案在 f[n]；每个状态只依赖前两项，所以 prev, cur 两个变量滚动即可，空间 O(1)。边界在 n = 0：循环不执行，直接返回 cur = 1；n = 45 时答案是 1836311903，仍在 int32 内，n = 46 就要溢出。 运行结果

4.2 0322 Coin Change（Medium） ​

题目要点：给一组面值可用任意多次的硬币，凑出 amount 所需的最少硬币数，凑不出返回 -1。 教学实现

go
func CoinChange(coins []int, amount int) int { // dp[v] = 凑出金额 v 的最少硬币数，凑不出返回 -1
	const inf = math.MaxInt32
	dp := make([]int, amount+1)
	for i := range dp {
		dp[i] = inf
	}
	dp[0] = 0
	for _, coin := range coins {
		for v := coin; v <= amount; v++ {
			dp[v] = min(dp[v], dp[v-coin]+1)
		}
	}
	if dp[amount] == inf {
		return -1
	}
	return dp[amount]
}

讲解：状态 dp[v] 是「凑出金额 v 的最少硬币数」，转移取 min(dp[v-coin]+1)——按「最后放进去的那枚硬币是哪种」分类。初始值只有 dp[0] = 0 有意义，其余格子先填 math.MaxInt32 表示不可达；dp[v-coin]+1 永远比哨兵大，凑不出的格子不会被更新，最后 dp[amount] 还是哨兵就返回 -1。为什么容量正序遍历：硬币在外层、容量在内层正序，意味着 dp[v-coin] 可能已经用过当前这枚硬币，于是同一种硬币能取任意多枚，这就是完全背包；容量若倒序，dp[v-coin] 一定还没用过当前硬币，每种硬币只能取一次，0/1 背包。题面说硬币数量无限，所以必须正序。答案在 dp[amount]。 运行结果

4.3 0053 Maximum Subarray（Medium） ​

题目要点：求和最大的连续子数组，题目要求子数组非空。 教学实现

go
func MaxSubArray(nums []int) int { // current = 以当前元素结尾的最大子段和，best = 全局最大
	best, current := nums[0], nums[0]
	for _, v := range nums[1:] {
		current = max(v, current+v) // 接在前面那段后面，还是从 v 重新开始
		best = max(best, current)
	}
	return best
}

讲解：状态 current 是「以当前元素结尾的最大子段和」，best 是「到目前为止的最大子段和」。转移只有两个选择：接在前面那段后面（current + v），或从当前元素重新开始（v），取大的那个就够——前面那段是负数时拖着走只会更差。初始值必须取 nums[0] 而不是 0：题目要非空子数组，best = 0 会让全负数组返回 0。答案不在某个固定下标上，而在滚动过程中不断更新的 best 上，这是线性 DP 最常见的答案位置。分治是另一种摆法：区间 [l,r] 的最优解要么全在左半边、全在右半边，要么跨中点；跨中点的最优值 = 「以 mid 结尾的最大和」+「以 mid+1 开头的最大和」，合并 O(n)、递归 O(log n) 层，整体 O(n log n)，比 Kadane 慢，但需要区间信息或复合状态时才划算。 运行结果

4.4 0337 House Robber III（Medium） ​

题目要点：二叉树上的打家劫舍，相邻（父子）节点不能同时被偷，求能偷到的最大金额。 教学实现

go
type TreeNode struct {
	Val   int
	Left  *TreeNode
	Right *TreeNode
}

// Rob 返回在二叉树上能偷到的最大金额（相连节点不能同时偷）：状态是 (偷根的最优, 不偷根的最优)。
func Rob(root *TreeNode) int {
	rob, skip := robSubtree(root)
	return max(rob, skip)
}

func robSubtree(node *TreeNode) (int, int) {
	if node == nil {
		return 0, 0
	}
	leftRob, leftSkip := robSubtree(node.Left)
	rightRob, rightSkip := robSubtree(node.Right)
	rob := node.Val + leftSkip + rightSkip
	skip := max(leftRob, leftSkip) + max(rightRob, rightSkip)
	return rob, skip
}

讲解：状态不是「一棵子树能偷多少」，而是两个值 (偷根时的最优, 不偷根时的最优)——只返回一个 max(rob, skip) 会丢掉信息，因为父节点需要知道「这棵子树被强制偷」的情形。转移分两种：偷根则两个孩子都不能偷，得 node.Val + leftSkip + rightSkip；不偷根则两个孩子互不相干，各取 max(rob, skip) 即可。初始值是空树的 (0, 0)，答案在根节点的 max(rob, skip) 上。空间 O(h) 是递归栈，树退化成链时 h = n。 运行结果

4.5 0698 Partition to K Equal Sum Subsets（Medium） ​

题目要点：把 n 个数分成 k 个非空子集，各子集和相等则返回 true。 教学实现

go
func CanPartitionKSubsets(nums []int, k int) bool { // bucket[j] 是第 j 个桶的累加和，target = 总和 / k
	if k <= 1 {
		return true
	}
	total := 0
	for _, v := range nums {
		total += v
	}
	if total%k != 0 {
		return false
	}
	target := total / k
	sorted := slices.Clone(nums)
	slices.SortFunc(sorted, func(a, b int) int { return b - a }) // 降序，大数先放
	if len(sorted) == 0 || sorted[0] > target {
		return false
	}
	return partitionDFS(sorted, make([]int, k), target, 0)
}
func partitionDFS(sorted, bucket []int, target, idx int) bool {
	if idx == len(sorted) {
		return true
	}
	v := sorted[idx]
	for j := range bucket {
		// 同和的桶互相等价；装不下的桶直接跳过
		if (j > 0 && bucket[j] == bucket[j-1]) || bucket[j]+v > target {
			continue
		}
		bucket[j] += v
		if partitionDFS(sorted, bucket, target, idx+1) {
			return true
		}
		bucket[j] -= v
		if bucket[j] == 0 {
			break // 空桶都放不下，换个空桶同样不行
		}
	}
	return false
}

讲解：状态是「每个桶当前的累加和」bucket[j]，目标 target = 总和/k，把降序后的数依次丢进桶里，放得下就放，全部放完即成功。三条剪枝是这道题的全部难度：① 降序排序，大数先放，冲突提前暴露；② 同和的桶互相等价（bucket[j] == bucket[j-1] 时只试一个），否则大量等价分支会被重复搜索；③ 空桶失败就直接 break，换另一个空桶同样装不下。前置剪枝有三条：总和不能被 k 整除、任何元素都不能大于 target（案例 2：nums=[1,2,3], k=3 时 target=2，而元素 3 本身就超了）、空数组。这题用回溯而不是状压 DP：要求「列出全部方案」时回溯更合适，n ≤ 16 的约束正是剪枝能奏效的前提；真要上 DP，状态是 dp[mask]（已放入元素的位掩码），2^16 = 65536 个状态也放得下，但常数更大。 运行结果

4.6 1140 Stone Game II（Medium） ​

题目要点：Alice 与 Bob 轮流从左端取走前 X 堆（1 ≤ X ≤ 2M），取完更新 M = max(M, X)，求最优对弈下 Alice 拿到的石子数。 教学实现

go
// StoneGameII 返回双方都最优时 Alice 拿到的石子数：f(i, m) = 从 piles[i:] 起、上限为 m 时轮到走的一方最多能拿多少。
func StoneGameII(piles []int) int {
	n := len(piles)
	suffix := make([]int, n+1)
	for i := n - 1; i >= 0; i-- {
		suffix[i] = suffix[i+1] + piles[i]
	}
	memo := make([]int, n*(n+1))
	for i := range memo {
		memo[i] = -1 // -1 表示未计算；0 是合法答案，不能拿来当哨兵
	}
	var f func(i, m int) int
	f = func(i, m int) int {
		if i+2*m >= n {
			return suffix[i] // 一次能拿完剩下的所有堆
		}
		key := i*(n+1) + m
		if memo[key] != -1 {
			return memo[key]
		}
		opponent := suffix[i]
		for x := 1; x <= 2*m; x++ {
			opponent = min(opponent, f(i+x, max(m, x)))
		}
		memo[key] = suffix[i] - opponent
		return memo[key]
	}
	return f(0, 1)
}

讲解：这是零和博弈，两人拿到的总和恒等于剩余石子总数，所以「我方拿多少 = 总量 − 对方拿多少」。状态 f(i, m) 是「从 piles[i:] 开始、当前可取上限为 m 时，轮到走的一方最多能拿多少」——不必记「轮到谁」，因为零和且规则对双方相同。转移对对手的结果取 min：我方最大化自己 = 最小化对方，f(i,m) = suffix[i] − min over x of f(i+x, max(m,x))。同一式子的另一副面孔是「最大差」：先手能拿到的最大差 = suffix[i] − 2 × 对方最优。基例 i+2m ≥ n：当前玩家能一次拿完，答案是 suffix[i]。初始状态 f(0, 1)，记忆化哨兵用 -1（0 是合法答案）。状态数 O(n^2)、每状态枚举 2m 个 x，整体 O(n^3)。 运行结果

func CoinChange(coins []int, amount int) int { // dp[v] = 凑出金额 v 的最少硬币数，凑不出返回 -1

		}
	}

		return -1

5. 变体与边界 ​

  1. 背包的正序与倒序：0322 的容量正序是完全背包；若题面改成「每种硬币最多用一次」（0416 Partition Equal Subset Sum（Medium）），容量必须倒序遍历，否则同一枚硬币会被重复使用。
  2. 树形 DP 返回值的变化：0337 返回两个值（取 / 不取），0124 Binary Tree Maximum Path Sum（Hard） 要返回三个（单边最优、双边最优、单点最优），1530 Number of Good Leaf Nodes Pairs（Medium） 返回的是计数而不是金额。
  3. 博弈 DP 的两种口径：f = 总量 − min(对手) 与「最大差 = 自己 − 对手」等价；0877 Stone Game（Medium） 可以只用奇偶位结论，1140 必须老老实实做 DP。
  4. 同一个状态换口径：0053 只要和值时 Kadane 的 O(n) / O(1) 最优；0486 Predict the Winner（Medium） 要的是差值，就把状态直接定义成差。

6. 常见错误 ​

  1. 0070 的 f[0] 写成 0：递推从 f[1] 就断档，n=2 会算成 1。
  2. 0322 容量倒序遍历：每种硬币只能取一次，求出的是 0/1 背包的答案；题面说硬币无限，必须正序。
  3. 0053 初始值取 0：全负数组返回 0，违反「子数组非空」。
  4. 0337 只返回一个值：父节点分不清「这棵子树被强制偷」和「随便」，必须返回 (rob, skip) 两个值；1140 同理：记忆化哨兵用 0 会把真实答案当成缓存命中，必须用 -1。
