08 二分查找 ​

本质：在一个可判定的单调方向上，每轮砍掉一半可能区间。适合：答案在整数区间里，或要在有序结构中找边界。

1. 场景 ​

二分的输入有两种形态。一种是数组已经有序或半有序，要的是某个位置（0033、0034）；另一种是答案不是位置而是一个数——最小速度、最小段和上限——要在一个整数区间里找最值（0875、0410）。

决定性条件藏在约束里。0875 给了 piles.length <= h，于是区间 [1, max(piles)] 必定含解；0410 的答案必然落在 [max(nums), sum(nums)] 之间。约束一旦到位，二分的两端就定死了，不用再写「二分失败怎么办」的兜底分支。

认出信号：题面出现「最小的 k」「最小代价」「最多切成 m 段」「第一个 ≥ x 的位置」，或者明写要求 O(log n)。此时先别写代码，先把答案区间和判定函数这两样写在纸上。

2. 核心机制 ​

骨架只有一句话：维护一个「答案仍在其中」的区间 [lo, hi]，每轮取中点，用某个单调的判定把区间砍掉一半。单调性是唯一的入场券——判定一旦失去单调，被砍掉的那一半就可能藏着答案。

判定有两个来源。一类是位置单调：数组有序，nums[i] >= x 随 i 单调（0034 的 lowerBound）。另一类是答案单调：把候选答案代进判定函数，得到一条真假序列（0875 的 hours(k) 随 k 单调不增，0410 的 groupsNeeded(cap) 随 cap 单调不增）。真假序列形如「假假假真真真」，二分找的正是第一次为真的位置。

中点取整方式跟判定方向绑定：找「第一个为真」用 mid = lo + (hi-lo)/2 配 hi = mid；找「最后一个为真」用 mid = lo + (hi-lo+1)/2 配 lo = mid，那个 +1 是防死循环的，不是可选项。0033 是另一种形态：数组整体不单调，但每一半至少有一半完全没被旋转过，于是可以用一次值域比较决定方向。它靠的不是单调性，而是「局部有序 + 一次比较定位」。所以二分的前提不是「数组有序」，而是答案能被单调地二分。

3. 套路清单 ​

套路做法复杂度备注
值域二分（找最小可行值）在 [lo,hi] 上二分，check(x) 单调不增，答案是第一个为真的位置O(log V × check)V 是答案取值范围，V 到 10^9 就是 30 轮
判定二分（最大化最小值）check(x) 单调不减，答案是最后一个为真的位置O(log V × check)中点改上取整并配 lo = mid，别和上一行混用

半有序数组（旋转）每轮判断哪半有序，用有序半的值域比较决定往哪边走O(log n) / O(1)依赖元素互不相同；有重复值时最坏退化成 O(n)

4.1 0033 Search in Rotated Sorted Array（Medium） ​

题目要点：升序数组在某个未知位置旋转过，元素互不相同；返回 target 的下标，不存在返回 -1，要求 O(log n)。

教学实现

go
// searchRotated 返回 target 在旋转有序数组中的下标，不存在返回 -1。
func searchRotated(nums []int, target int) int {
	lo, hi := 0, len(nums)-1
	for lo <= hi {
		mid := lo + (hi-lo)/2
		if nums[mid] == target {
			return mid
		}
		if nums[lo] <= nums[mid] {
			// 左半段有序：target ∈ [nums[lo], nums[mid]) 就在左半段
			if nums[lo] <= target && target < nums[mid] {
				hi = mid - 1
			} else {
				lo = mid + 1
			}
		} else if nums[mid] < target && target <= nums[hi] {
			// 右半段有序，且 target 落在 (nums[mid], nums[hi]]
			lo = mid + 1
		} else {
			hi = mid - 1
		}
	}
	return -1
}

讲解：每轮用 mid 把数组切成两段，至少有一段完全没被旋转过，所以「哪半有序」是一次比较的事：nums[lo] <= nums[mid] 就是在问「左半段有序吗」。左半段有序时，target 若落在 [nums[lo], nums[mid]) 就一定在左半段，可以整段丢掉右半段；右半段有序时用对称的 (nums[mid], nums[hi]] 判定。两个区间都排除了 mid（它刚比过），所以不漏也不重。

边界靠三个细节兜住：nums[mid] == target 必须先返回，否则会漏掉正好落在 mid 上的答案；判断用 <= 而不是 <，因为 lo == mid 时左半段只剩一个元素，也得算有序；循环退出（lo > hi）说明没找到，返回 -1 而不是 0。数组没被旋转过时，nums[lo] <= nums[mid] 恒成立，这段代码自动退化成标准二分。

运行结果

text
nums=[4 5 6 7 0 1 2] target=0 -> 4
nums=[4 5 6 7 0 1 2] target=3 -> -1
nums=[1] target=0 -> -1

4.2 0034 Find First and Last Position of Element in Sorted Array（Medium） ​

题目要点：非降序数组里 target 可能出现多次，要返回它出现的首末下标；不存在返回 [-1, -1]，要求 O(log n)。

教学实现

go
// searchRange 返回 target 出现的首末下标；不存在返回 [-1, -1]。
func searchRange(nums []int, target int) []int {
	first := lowerBound(nums, target)
	if first == len(nums) || nums[first] != target {
		return []int{-1, -1}
	}
	return []int{first, lowerBound(nums, target+1) - 1}
}

// lowerBound 返回第一个 >= x 的下标；都比 x 小则返回 len(nums)。
func lowerBound(nums []int, x int) int {
	lo, hi := 0, len(nums)
	for lo < hi {
		mid := lo + (hi-lo)/2
		if nums[mid] < x {
			lo = mid + 1
		} else {
			hi = mid
		}
	}
	return lo
}

讲解：lowerBound(nums, x) 是这类题的核心原语——返回第一个 >= x 的下标，全都小于 x 时返回 len(nums)。它用半开区间 [lo, hi) 写：nums[mid] < x 说明 mid 及其左边都太小，lo = mid+1；否则 hi = mid，把 mid 本身留作候选，循环结束时 lo 就是答案位置。找首末位置只调用它两次：first = lowerBound(target)，last = lowerBound(target+1) - 1——第一个严格大于 target 的位置往前挪一格，就是最后一个 target。这比写两个对称的二分模板更不容易错，因为两套模板的手感相反、边界符号容易串。

两个必须查的边界：lowerBound 可能返回 len(nums)（target 比所有元素都大），此时取 nums[first] 会越界 panic；还要查 nums[first] != target，因为 target 不存在但数组里有更大元素时，first 指向的是比 target 大的第一个位置。另外 target+1 在 target 撞上 int 上界时会溢出，本题把 target 限在 10^9 所以碰不到，要写通用库就换成 upperBound 写法。

运行结果

text
nums=[5 7 7 8 8 10] target=8 -> [3 4]
nums=[5 7 7 8 8 10] target=6 -> [-1 -1]
nums=[] target=0 -> [-1 -1]

4.3 0875 Koko Eating Bananas（Medium） ​

题目要点：每小时只吃一堆、每堆最多吃 k 个，最多吃 h 小时，求最小速度 k。

教学实现

go
// minEatingSpeed 返回能在 h 小时内吃完所有香蕉的最小速度 k。
func minEatingSpeed(piles []int, h int) int {
	hi := 1
	for _, p := range piles {
		hi = max(hi, p)
	}
	lo := 1
	for lo < hi {
		mid := lo + (hi-lo)/2
		if canFinish(piles, mid, h) {
			hi = mid
		} else {
			lo = mid + 1
		}
	}
	return lo
}

// canFinish 判断速度 k 能否在 h 小时内吃完；累加超过 h 就提前退出。
func canFinish(piles []int, k, h int) bool {
	var hours int64
	for _, p := range piles {
		hours += (int64(p) + int64(k) - 1) / int64(k) // ceil(p/k)
		if hours > int64(h) {
			return false
		}
	}
	return true
}

讲解：先把「速度 k 要几小时」写成函数：hours(k) = Σ ceil(piles[i]/k)。题面说每小时只吃一堆、这一小时不再吃别的，所以各堆的小时数是相加而不是取最大——写成「每堆单独判断 ≤ h」是本题最容易犯的语义错。ceil(p/k) 用 (p+k-1)/k 算，纯整数、无浮点误差；p < k 时结果正好是 1，对应题面「不够 k 个就吃完这堆、这一小时不再吃别的」。

单调性也在这里：k 越大 ceil 越小，hours 单调不增，于是「hours(k) ≤ h」是一条先假后真的谓词，答案就是它第一次为真的位置。区间取 [1, max(piles)]：k = max(piles) 时每堆正好一小时，hours = n ≤ h，题面的 piles.length <= h 保证这个上界一定可行，所以不需要兜底分支。累加器必须用 int64——n = 10^4 堆 10^9 时 k=1 的总小时数是 10^13，int32 会溢出，而这个 bug 在样例上永远暴露不出来。

运行结果

text
piles=[3 6 7 11] h=8 -> 4
piles=[30 11 23 4 20] h=5 -> 30
piles=[30 11 23 4 20] h=6 -> 23

4.4 0410 Split Array Largest Sum（Hard） ​

题目要点：把 nums 切成 m 个连续段，最小化「各段和的最大值」。

教学实现

go
// splitArray 返回把 nums 切成 m 个连续段后「各段和最大值」的最小可能值。
func splitArray(nums []int, m int) int {
	lo, hi := 0, 0
	for _, v := range nums {
		lo = max(lo, v) // 下界：最大元素，单独一段也装得下
		hi += v         // 上界：整段之和
	}
	for lo < hi {
		mid := lo + (hi-lo)/2
		if groupsNeeded(nums, mid) <= m {
			hi = mid
		} else {
			lo = mid + 1
		}
	}
	return lo
}

// groupsNeeded 返回「每段和不超过 cap」时贪心切出的最少段数。
func groupsNeeded(nums []int, cap int) int {
	groups, cur := 1, 0
	for _, v := range nums {
		if cur+v > cap {
			groups++
			cur = v
		} else {
			cur += v
		}
	}
	return groups
}

讲解：这里二分的是答案本身——段和上限 cap。给定 cap 就贪心地切：每段尽量装满，装不下就另起一段，得到的就是 cap 约束下的最少段数。贪心为什么对：段和上限固定时，每一刀尽量往后挪，剩下的元素只会更少而不是更多，段数不会比任何别的切法更多，所以 groupsNeeded(cap) 恰好是「这个 cap 下最少要几段」。

单调性随之而来：cap 越大段数越少或不变，「groupsNeeded(cap) ≤ m」是先假后真的谓词，答案就是第一个为真的 cap。区间是 [max(nums), sum(nums)]：下界是最大元素（任何元素都得整段装下），上界是总和（一段装完）。m = 1 时答案就是 sum，二分也会自动收敛到它，仓库实现用 m == 1 短路省掉了这轮扫描。

运行结果

text
nums=[7 2 5 10 8] m=2 -> 18
nums=[7 2 5 10 8] m=1 -> 32
nums=[7 2 5 10 8] m=5 -> 10

仓库实现：0410-split-array-largest-sum/solution.go

5. 变体与边界 ​

  1. 元素有重复的旋转数组（0154）：nums[lo] == nums[mid] 时判断不出哪半有序，只能 lo++ 试探，最坏退化成 O(n)。
  2. 找「最后一个 ≤ x 的位置」：把 lowerBound 换成 upperBound（判 nums[mid] <= x），比 lowerBound(x+1)-1 更耐整数溢出。
  3. 「最小化最大值」反过来成「最大化最小值」：判定方向反转，答案是最后一个为真的位置，中点必须改用上取整 lo+(hi-lo+1)/2，否则死循环。
  4. 答案不是位置而是「最接近 x 的元素」：二分定位到 lowerBound 后，和它前一个元素比距离，别在二分过程里做比较。

6. 常见错误 ​

  1. mid 取整方式跟 hi = mid / hi = mid - 1 混用：上取整配 lo = mid 会死循环，下取整配 lo = mid 会漏解。改法：找第一个为真用下取整配 hi = mid，找最后一个为真用上取整配 lo = mid。
  2. lowerBound 返回 len(nums) 后直接取 nums[first]：越界 panic。改法：先判 first == len(nums) 再取值。
  3. 0875 把「总小时数 ≤ h」写成「每堆小时数 ≤ h」：小时是加的不是取最大的。改法：先累加总和再比 h。
  4. 0875 的累加器用 int：n = 10^4 堆 10^9 时总和是 10^13，int32 会溢出。改法：累加器一律用 int64。
