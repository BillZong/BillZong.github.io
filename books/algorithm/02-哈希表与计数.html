02 哈希表与计数 ​

用空间换时间，把「找过没有、数过几次、上次在哪」压成一次 O(1) 查询。 适合：判重复、统计频次、记录位置、O(1) 判存在。

1. 场景 ​

这类题的输入几乎都是一维序列（数组、字符串），问的却不是「序列长什么样」，而是关于元素的统计事实：某个值出现过没有？出现了几次？上次出现在哪？和某个值配对的元素在哪。

约束里往往藏着决定性条件。0001 的进阶提示直接写明「时间复杂度小于 O(n²)」；0128 写死「必须 O(n)」。这两句话一出口，排序和动态规划都被排除，只剩哈希表这条路。

认出这类题的信号有三个：暴力解是 O(n²) 而 n 很大；要求均摊 O(1) 的查询；题面出现「每个元素出现 k 次」「上次出现的位置」「均匀随机取一个」。反过来，需要保序或范围查询时，map 不该上。

2. 核心机制 ​

一句话：哈希表把「键 → 值」的查找从 O(n) 压到 O(1)（均摊），代价是 O(n) 空间和常数级的哈希开销。

0001 的推导最短。朴素写法对每个 i 去找 target - nums[i] 在哪，代价 O(n²)。但真正需要的信息只有「已经扫过的那些值分别在哪」——把这一句变成数据结构，就是一张 map[int]int。循环每走一步查一次表，总代价降到 O(n)。

关键在于哈希表在这里不是「集合」，而是带时间戳的记录：表里存的永远是「到目前为止发生过什么」。0001 存「值 → 下标」，问「补数出现过吗」；0128 存「值 → 在不在」，问「我是某段的起点吗」；0560 存「前缀和 → 出现过几次」，问「历史上多少个前缀和等于 cum-k」；0380 存「值 → 在数组里的槽位」，问「它在第几个」。四种问法，一句话概括：把问题里「跟过去有关」的那部分状态存进表。

0380 值得单独看一眼，它演示了哈希表和数组如何分工：数组负责「按下标随机取」，哈希表负责「按下标找到值」，两者互为索引，删除时才不用搬移。

text
vals = [a, b, c, d]      idx = {a:0, b:1, c:2, d:3}
删除 b（下标 1）：
  末元素 d 换到下标 1  →  vals = [a, d, c]
  idx[d] 改成 1         →  idx = {a:0, d:1, c:2}
  截掉末尾              →  vals = [a, d]

3. 套路清单 ​

套路做法复杂度备注
找配对边遍历边查表，把扫过的值连同下标存进 map，命中补数就返回时间 O(n)，空间 O(n)补数是 target-v 不是 target+v；必须先查后写，否则元素和自己配对
频次统计map[K]int 计数一遍，再扫表取频次最大/最小的键时间 O(n)，空间 O(m)m 是键的种类数；键要选真正的不变量，别用会被改写的对象
位置记录map[K]int 存最近一次出现的下标，用当前下标减它得到距离时间 O(n)，空间 O(n)「最近」和「最早」差一个方向，写之前先确认要哪个
前缀和计数表里存每个前缀和出现的次数，count[0]=1 起步时间 O(n)，空间 O(n)前缀和会重复（数组含负数），必须计数不能只判存在
起点判断集合里没有 x-1 才从 x 向后延伸时间 O(n)，空间 O(n)每个元素最多被走两次；不判起点就退化成 O(n²)
下标映射数组存元素本体，map 记元素槽位，删除时与末尾交换时间 O(1)，空间 O(n)先更新末元素槽位再删自己，末元素可能就是自己

4. Go 实现 ​

4.1 0001 Two Sum（Easy） ​

题目要点：给定整数数组和目标值，返回和为目标值的两个不同下标。题目保证答案唯一，且不能复用同一个元素。

教学实现

go
func TwoSum(nums []int, target int) []int {
	seen := map[int]int{} // 值 -> 下标
	for i, v := range nums {
		if j, ok := seen[target-v]; ok { // 补数已经出现过
			return []int{j, i}
		}
		seen[v] = i // 先查后写：查表在前，把自己放进去在后
	}
	return nil
}

讲解：seen 里只装已经扫过的元素，所以命中时 j 必然小于 i，两个下标天然不同，不可能拿同一个元素用两次。顺序上必须「先查补数、再写自己」：若先写 seen[v] = i，那么 target == 2*v 时元素会和自己配对，[3,3] 配 target=6 会返回 [0,0]。命中判断要用 if j, ok := seen[target-v]; ok 的双返回形式，而不是 if j := seen[target-v]; j != 0——下标 0 是合法下标，零值判空会把真命中当成没命中。最后的 return nil 在合法输入下不可达（题目保证有解），但 Go 少一个 return 过不了 vet，所以留着。

运行结果

case 2 重复元素    : nums=[3 3] target=6  -> [0 1]
case 3 负数与极值  : nums=[-1000000000 1000000000 7] target=0  -> [0 1]
case 4 无解        : nums=[1 2 3] target=100 -> <nil>

4.2 0128 Longest Consecutive Sequence（Medium） ​

题目要点：给定无序数组，返回最长连续整数序列的长度，题目要求 O(n) 时间。

教学实现

go
func LongestConsecutive(nums []int) int {
	set := make(map[int]bool, len(nums))
	for _, v := range nums {
		set[v] = true
	}
	best := 0
	for _, v := range nums {
		if set[v-1] {
			continue // 不是起点，跳过
		}
		length := 1
		for set[v+length] {
			length++
		}
		if length > best {
			best = length
		}
	}
	return best
}

讲解：集合去重是白送的，两个 0 只算一个元素，所以重复值不需要额外处理。set[v-1] 是「我是不是起点」的判据，也是这题 O(n) 的全部秘密：少了它，同一段连续序列会被每个元素各扫一遍，退化成 O(n²)；有了它，每个元素最多被走两次（一次作为起点候选，一次作为前驱的延伸），总代价就是 O(n)。best 初值取 0，空数组时循环体根本不执行，直接返回 0，不用特判。官方的示例 2 输出写的 9 是题面笔误：去重后集合是 {0,2,3,4,5,6,7,8}，最长的连续段是 2..8 共 7 个，仓库单测里的期望值同样是 7。v-1 在 v 取最小值 -10^9 时也不会溢出，不需要额外保护。

运行结果

text

case 2 题面示例    : nums=[0 3 7 2 5 8 4 6 0] -> 7   (官方示例写的 9 是题面笔误, 正确答案是 7)

4.3 0560 Subarray Sum Equals K（Medium） ​

题目要点：给定整数数组和 k，返回和恰好为 k 的连续子数组个数。数组含负数。

教学实现

go
func SubarraySum(nums []int, k int) int {
	count := map[int]int{0: 1} // 空前缀：子数组从头开始的情况
	cum, ans := 0, 0
	for _, v := range nums {
		cum += v
		ans += count[cum-k] // 历史上每个等于 cum-k 的前缀和都对应一个答案
		count[cum]++
	}
	return ans
}

讲解：推导只有一行——设 cum(i) 是前 i 个数的和，则 nums[l..r] 的和等于 cum(r+1) - cum(l)，要求它等于 k 就得让 cum(l) = cum(r+1) - k，所以每走到一个右端点，就去问表里「有多少个前缀和等于 cum-k」。count[0] = 1 代表空前缀，它对应「子数组从下标 0 开始」这一类，少了它所有从头算起的子数组都数不到。循环体里 ans += count[cum-k] 必须排在 count[cum]++ 前面：反过来在 k=0 时 cum-k == cum，当前前缀和会把自己当成前驱，凭空多算一个长度为零的子数组。这里必须计数而不是判存在，因为数组含负数时同一个前缀和会多次出现，每一次都是一个不同的左端点。补数方向是 cum-k 而不是 cum+k，写反了答案会变成另一个问题的答案。

运行结果

text

case 2 题面示例    : nums=[1 -1 0] k=0 -> 3

4.4 0380 Insert Delete GetRandom O(1)（Medium） ​

题目要点：实现一个集合，Insert、Remove、GetRandom 三个操作都要求平均 O(1)。GetRandom 必须均匀。

教学实现（完整文件顶部需要 import "math/rand"）

go
type RandomizedSet struct {
	idx  map[int]int // 值 -> 在 vals 中的槽位
	vals []int       // 元素本体，GetRandom 靠它随机取下标
	rnd  *rand.Rand  // 独立随机源，固定种子即可复现
}

func NewRandomizedSet(seed int64) *RandomizedSet {
	return &RandomizedSet{idx: map[int]int{}, rnd: rand.New(rand.NewSource(seed))}
}

func (s *RandomizedSet) Insert(val int) bool {
	if _, ok := s.idx[val]; ok {
		return false
	}
	s.idx[val] = len(s.vals)
	s.vals = append(s.vals, val)
	return true
}

func (s *RandomizedSet) Remove(val int) bool {
	i, ok := s.idx[val]
	if !ok {
		return false
	}
	last := s.vals[len(s.vals)-1]
	s.vals[i] = last
	s.idx[last] = i // 必须先改末元素的槽位，再删 val：last 可能就是 val 自己
	delete(s.idx, val)
	s.vals = s.vals[:len(s.vals)-1]
	return true
}

func (s *RandomizedSet) GetRandom() int {
	return s.vals[s.rnd.Intn(len(s.vals))]
}

讲解：两个容器分工明确：vals 是数组本体（下标随机取靠它），idx 是值到槽位的映射（O(1) 找位置靠它），只有 map 没有数组做不到 O(1) 随机取，只有数组没有 map 则删除要 O(n)。Insert 先查 idx 判重再 append，保证 vals 里没有重复元素——这是「均匀」的前提，重复会让某些值被抽中的概率更高。Remove 里 s.idx[last] = i 必须在 delete(s.idx, val) 之前：被删的元素若正好在末尾则 last == val，先删再写会把刚删掉的键重新塞回表里，集合从此多出一个幽灵元素。用「与末尾交换」而不是搬移，是把删除从 O(n) 压到 O(1) 的唯一办法，代价是元素物理顺序被打乱——本题不要求顺序，所以可以接受。GetRandom 抽的是下标不是键，每个元素的概率严格是 1/len(vals)，均匀性由此保证。空集合上调 GetRandom 会 panic（rand.Intn(0)），LeetCode 保证调用时集合非空，仓库把这条记在 NOTE 的「可改进点」里，教学版保持同样行为、不加哨兵。

5. 变体与边界 ​

  1. 从「有没有」到「有几个」：0001 和 0560 用的是同一种表，前者存下标、后者存次数。题目从「是否存在」升级到「有多少种方式」时，把 map[K]bool 换成 map[K]int 计数即可；0347 Top K Frequent Elements 是再加一层：计数之后按频次分桶，倒着取第 K 个桶。
  2. 值域已知时用桶换 map：0705 Design HashSet 和 0706 Design HashMap 的键值域都是 [0, 10^6]，这种有上界的值域用桶数组当底层结构比通用 map 更省。两题更进一步，题面明确禁止使用内建哈希表：仓库的实现里 0705 用桶头数组 + 手写单链表（分离链），0706 用扁平数组 + 线性探测 + 墓碑标记（开放寻址），删除时不能直接清空槽位，否则会把探测链截断。
  3. 键与方向的选择：分组靠键（0049 Group Anagrams 把排序后的字符串当键，0242 Valid Anagram 只需要 26 个字母的计数数组）；判定同构要两张表（0205 Isomorphic Strings 是 map[byte]byte 加 map[byte]byte），只有一张表会把两个不同字符映到同一个目标字符上。
  4. 要求保序就不能原地换位：0380 的「与末尾交换」打乱了顺序。如果题目额外要求「删除后剩余元素保持原相对顺序」，删除就得退化成 O(n) 搬移，或者换成有序结构——哈希表本身不保证顺序，这是它和树、平衡树的根本分工。

6. 常见错误 ​

  1. 先存后查 / 用零值判命中：0001 里先把整个数组塞进 map 再找补数，元素会和自己配对，[3,3] 配 target=6 会返回 [0,0]；命中判断又写成 if j := seen[target-v]; j != 0，而下标 0 是合法下标。改成边遍历边查边写，并用 v, ok := m[k] 的 ok 形式。
  2. 只判存在不记次数：0560 里前缀和会重复（数组含负数），用 map[int]bool 会少算；必须 map[int]int 计数，且 count[0]=1 不能漏。
  3. 0128 不判起点：少了 set[v-1] 的判断，同一段连续序列会被每个元素各扫一遍，O(n²) 直接超时。
  4. 0380 删除时先 delete：delete(s.idx, val) 写在 s.idx[last] = i 前面，当被删元素就在末尾时会把刚删掉的键写回表里，集合从此多出一个幽灵元素；空集合上调 GetRandom 则会 panic（rand.Intn(0)），题目保证集合非空，但自己写单测时容易踩。
