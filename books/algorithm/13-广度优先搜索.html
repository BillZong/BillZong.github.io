13 广度优先搜索 ​

按距离分层扩展，无权图里第一次到达就是最短。 适合：求最短步数、按层输出、状态空间是一张隐式图。

1. 场景 ​

这类题的输入几乎总是一张「格子之间一步可达」的图：二叉树的父子边、矩阵的上下左右、或者带锁的迷宫；要求输出的也总是「最少几步」或「按层分组」。

决定性条件不在形状里，在代价里：每条边的代价都一样。只要出现「绕远一点更划算」（边权不同），BFS 立刻失效，得换 Dijkstra。另一条信号是「状态里带着历史」：能不能从 u 走到 v 取决于你手里有什么——这时节点不再是格子，而是「格子 + 状态」；认出信号有三句话：要最短步数、答案按层分组、约束里写着「四方向相邻」「钥匙只有 6 把」这种状态规模提示。

2. 核心机制 ​

BFS 只做一件事：把队列里的节点一层一层往外推。队列里的节点永远按距离非递减的顺序出队——先入队的一定更近。推论就是「第一次到达即最短」：某个格子第一次被访问时，它的距离已经是最小值。多源 BFS 是同一套机制换个起点：把所有源点一次性放进队列，等价于在图上加一个超级源点、连一条零权边到每个源点，0994 的腐烂橘子与 0286 的门都属于这一类。

第三层是「状态带掩码」。0864 里同一个格子拿着不同的钥匙是两种不同的处境，所以 visited 的键必须是「位置 + 掩码」而不是位置；只记位置会剪掉「还没拿到钥匙」那条路，而且错得很安静——三道官方样例全都蒙得对。

3. 套路清单 ​

套路做法复杂度备注
层序遍历队列按层推进：先取完本层、攒好下一层，再整体替换时间 O(n)，空间 O(最宽层)不能边出队边往同一个队列 append，层边界会乱
无权最短路BFS，第一次入队时记距离、就打上访问标记时间 O(V+E)，空间 O(V)出队才打标记会重复入队，复杂度爆炸
多源 BFS所有源点一次性入队，从第 0 层一起扩时间 O(V+E)，空间 O(V)等价于加超级源点；别一个源点各跑一遍
状态压缩搜索队列里存「位置 + 状态编码」，visited 也用整个状态做键时间 O(V·S)，空间 O(V·S)状态要能区分不同处境，否则会静默剪错
网格最短路把矩阵当图，四方向展开，越界与墙跳过时间 O(mn)，空间 O(mn)边权不全相同时 BFS 不成立

4.1 0102 Binary Tree Level Order Traversal（Medium） ​

题目要点：给一棵二叉树，返回按层分组的节点值序列，每层从左到右；节点数上限 2000。 教学实现

go
// TreeNode 是二叉树节点。
type TreeNode struct {
	Val   int
	Left  *TreeNode
	Right *TreeNode
go
	for len(queue) > 0 {
		level, next := []int{}, []*TreeNode{}
		for _, n := range queue {
			level = append(level, n.Val)
			for _, c := range []*TreeNode{n.Left, n.Right} {
				if c != nil {
					next = append(next, c)
				}
			}
		}
		out = append(out, level)
		queue = next // 整层换成下一层，层边界自然形成
	}

讲解：队列里始终只装同一层的节点：本轮取完这一层、攒好下一层，再整体替换成 queue = next；for range queue 取的是切片头部的快照，所以这一层的孩子只能进 next，直接往同一个队列 append 会让层边界失效。out = append(out, level) 必须放在换层之前，次序反了整棵树就错位。空树返回 [][]int{} 而不是 nil，题面要的是空数组，测试里 nil 与空切片并不等价。

运行结果

text

  0102 root=[] -> []
  0102 root=[1] -> [[1]]

4.2 0994 Rotting Oranges（Medium） ​

题目要点：m×n 网格里 0 空、1 新鲜、2 已烂，每分钟与腐烂橘子四方向相邻的新鲜橘子变烂；求全部腐烂的最少分钟数，不可能则返回 -1。 教学实现（只贴每分钟的扩散循环，完整函数见 4.5）

go
	for fresh > 0 && len(queue) > 0 {
		next := [][2]int{} // 本轮只装「这一分钟刚烂掉」的橘子
		for _, cur := range queue {
			for _, d := range [4][2]int{{-1, 0}, {1, 0}, {0, -1}, {0, 1}} {
				nr, nc := cur[0]+d[0], cur[1]+d[1]
				if nr < 0 || nr >= m || nc < 0 || nc >= n || grid[nr][nc] != 1 {
					continue
				}
				grid[nr][nc] = 2 // 改成 2 就是「已访问」标记
				fresh--
				next = append(next, [2]int{nr, nc})
			}
		}
		queue = next
		minutes++
	}

讲解：多源的意思是「所有初始腐烂橘子同时入队」，等价于加一个超级源点；边扫边扩散会把后面的源点推迟至少一轮，分钟数偏大，这是这题最常见的错。轮次边界由「每轮一个新切片 next」保证：本轮新烂的橘子进 next、不会在本轮继续传播，所以「一分钟一格」成立，直接 append 回同一个队列会让答案偏小。grid[nr][nc] != 1 一条判断同时挡住越界、已烂的格子和本轮刚标记的格子，等于拿网格自身当 visited，代价是入参被改写。最后判 -1 的依据是「队列排空后还有没有新鲜橘子」。

  0994 grid=[[2 1 1] [0 1 1] [1 0 1]] -> -1
  0994 grid=[[0 2]] -> 0

4.3 0286 Walls and Gates（Medium） ​

题目要点：m×n 网格里 -1 是墙、0 是门、其余是空房间；把每个空房间填成到最近门的距离，填不了（没有门可达）保持原值。 教学实现（只贴从门扩散填距离的循环，完整函数见 4.5）

go
	for len(queue) > 0 {
		cur := queue[0]
		queue = queue[1:]
		for _, d := range [4][2]int{{1, 0}, {-1, 0}, {0, 1}, {0, -1}} {
			nr, nc := cur[0]+d[0], cur[1]+d[1]
			if nr < 0 || nr >= rows || nc < 0 || nc >= cols || rooms[nr][nc] != INF {
				continue
			}
			rooms[nr][nc] = rooms[cur[0]][cur[1]] + 1
			queue = append(queue, [2]int{nr, nc})
		}
	}

讲解：门是源点、空房间是待填格子、墙直接跳过，骨架和 0994 完全一样，区别只在三处：源点从「腐烂橘子」换成「门」；扩散时不是把邻居标记成 2，而是把 INF 改成父格距离加一；终点不是「全部填完」，而是「每个格子第一次被填到的值就是答案」。rooms[nr][nc] != INF 同时挡住了墙、门和已经填过距离的格子，所以每个房间只会被填一次。多源 BFS 的关键性质在这里变成了「到最近门的距离」：BFS 按距离递增扩展，第一次到达必然是最短的那条路。

4.4 0864 Shortest Path to Get All Keys（Hard） ​

题目要点：m×n 网格里 . 空地、# 墙、@ 起点、小写是钥匙、大写是锁；踩上钥匙就拿到，锁只有在对应钥匙在手时才走得进去；求拿齐所有钥匙的最少步数，拿不齐返回 -1。 教学实现（状态定义与状态转移，完整 BFS 骨架见 4.5）

go
// keyState 是 BFS 的状态：位置 + 已拿到的钥匙掩码（'a'..'f' 对应 bit 0..5）。
type keyState struct {
	row, col int
	keys     uint8
}
go
		st := keyState{nr, nc, cur.keys}
		switch {
		case ch >= 'a' && ch <= 'f':
			st.keys |= 1 << (ch - 'a')
		case ch >= 'A' && ch <= 'F' && cur.keys&(1<<(ch-'A')) == 0:
			continue
		}
		out = append(out, st)

讲解：普通网格 BFS 有个隐含前提——「能不能从 u 走到 v」只取决于位置；本题把它打破了：能不能踩进 A 取决于手上有没有 a，所以节点不是格子，而是 (位置, 钥匙掩码) 三元组，visited 的键也必须带上掩码。只按格子去重的错解是静默的：仓库的 NOTE 记过，三道官方样例它全答对，却在 30×30 的蛇形网格上直接返回 -1。掩码是 6 位（'a'..'f' 对应 bit 0..5），踩到钥匙就 OR 进去、只增不减；目标判据是掩码齐全而不是「站在某个格子」——官方 Example 1 的 8 步路线终点踩在 'b' 上，'B' 还锁着。

运行结果

text
  0864 grid=[@.a.. ###.# b.A.B] -> 8
  0864 grid=[@Aa] -> -1
  0864 grid=[... .Aa b@B] -> 4

4.5 完整可运行示例 ​

下面这份程序可直接 go run（只用标准库），包含本篇 4.1–4.4 的全部教学实现——代码与上面逐字一致（含注释）——以及覆盖全部用例的 main。

go
package main

import "fmt"

// TreeNode 是二叉树节点。
type TreeNode struct {
	Val   int
	Left  *TreeNode
	Right *TreeNode
}

// LevelOrder 返回二叉树的层序遍历：同一层从左到右排在一组里。
func LevelOrder(root *TreeNode) [][]int {
	if root == nil {
		return [][]int{}
	}
	out, queue := [][]int{}, []*TreeNode{root}
	for len(queue) > 0 {
		level, next := []int{}, []*TreeNode{}
		for _, n := range queue {
			level = append(level, n.Val)
			for _, c := range []*TreeNode{n.Left, n.Right} {
				if c != nil {
					next = append(next, c)
				}
			}
		}
		out = append(out, level)
		queue = next // 整层换成下一层，层边界自然形成
	}
	return out
}

// OrangesRotting 返回所有新鲜橘子烂完所需的最少分钟数，烂不完返回 -1。
func OrangesRotting(grid [][]int) int {
	m, n := len(grid), len(grid[0])
	fresh, minutes, queue := 0, 0, [][2]int{}
	for r, row := range grid {
		for c, v := range row {
			if v == 1 {
				fresh++
			} else if v == 2 {
				queue = append(queue, [2]int{r, c}) // 所有初始腐烂橘子同时入队
			}
		}
	}
	for fresh > 0 && len(queue) > 0 {
		next := [][2]int{} // 本轮只装「这一分钟刚烂掉」的橘子
		for _, cur := range queue {
			for _, d := range [4][2]int{{-1, 0}, {1, 0}, {0, -1}, {0, 1}} {
				nr, nc := cur[0]+d[0], cur[1]+d[1]
				if nr < 0 || nr >= m || nc < 0 || nc >= n || grid[nr][nc] != 1 {
					continue
				}
				grid[nr][nc] = 2 // 改成 2 就是「已访问」标记
				fresh--
				next = append(next, [2]int{nr, nc})
			}
		}
		queue = next
		minutes++
	}
	if fresh > 0 {
		return -1 // 队列排空仍有新鲜橘子：它们够不到任何腐烂源
	}
	return minutes
}

// WallsAndGates 就地改写 rooms：每个空房间填成到最近门的距离。
func WallsAndGates(rooms [][]int) {
	if len(rooms) == 0 || len(rooms[0]) == 0 {
		return
	}
	const INF = 1<<31 - 1
	rows, cols := len(rooms), len(rooms[0])
	queue := [][2]int{}
	for r, row := range rooms {
		for c, v := range row {
			if v == 0 {
				queue = append(queue, [2]int{r, c}) // 所有门同时入队，距离都是 0
			}
		}
	}
	for len(queue) > 0 {
		cur := queue[0]
		queue = queue[1:]
		for _, d := range [4][2]int{{1, 0}, {-1, 0}, {0, 1}, {0, -1}} {
			nr, nc := cur[0]+d[0], cur[1]+d[1]
			if nr < 0 || nr >= rows || nc < 0 || nc >= cols || rooms[nr][nc] != INF {
				continue
			}
			rooms[nr][nc] = rooms[cur[0]][cur[1]] + 1
			queue = append(queue, [2]int{nr, nc})
		}
	}
}

// keyState 是 BFS 的状态：位置 + 已拿到的钥匙掩码（'a'..'f' 对应 bit 0..5）。
type keyState struct {
	row, col int
	keys     uint8
}

// stepStates 返回从状态 cur 一步能走到的状态：
// 踩到钥匙就把那一位 OR 进掩码，锁只有在对应钥匙已在手上时才走得进去。
func stepStates(grid []string, cur keyState, m, n int) []keyState {
	var out []keyState
	for _, d := range [4][2]int{{-1, 0}, {1, 0}, {0, -1}, {0, 1}} {
		nr, nc := cur.row+d[0], cur.col+d[1]
		if nr < 0 || nr >= m || nc < 0 || nc >= n {
			continue
		}
		ch := grid[nr][nc]
		if ch == '#' {
			continue
		}
		st := keyState{nr, nc, cur.keys}
		switch {
		case ch >= 'a' && ch <= 'f':
			st.keys |= 1 << (ch - 'a')
		case ch >= 'A' && ch <= 'F' && cur.keys&(1<<(ch-'A')) == 0:
			continue
		}
		out = append(out, st)
	}
	return out
}

// ShortestPathAllKeys 返回拿齐所有钥匙的最少步数，拿不齐返回 -1。
func ShortestPathAllKeys(grid []string) int {
	m := len(grid)
	if m == 0 || len(grid[0]) == 0 {
		return -1
	}
	n := len(grid[0])
	var allKeys uint8
	start := keyState{row: -1}
	for r := range m {
		for c := range n {
			switch ch := grid[r][c]; {
			case ch == '@':
				start = keyState{r, c, 0}
			case ch >= 'a' && ch <= 'f':
				allKeys |= 1 << (ch - 'a')
			}
		}
	}
	if start.row < 0 {
		return -1 // 没有 '@'，无处可走
	}
	visited := map[keyState]bool{start: true}
	queue := []keyState{start}
	for steps := 0; len(queue) > 0; steps++ {
		next := []keyState{}
		for _, cur := range queue {
			if cur.keys == allKeys {
				return steps // 掩码齐全即达成目标，与站在哪无关
			}
			for _, st := range stepStates(grid, cur, m, n) {
				if !visited[st] {
					visited[st] = true
					next = append(next, st)
				}
			}
		}
		queue = next
	}
	return -1
}

func main() {
	specs := []string{"[3 9 20 null null 15 7]", "[]", "[1]"}
	trees := []*TreeNode{{Val: 3, Left: &TreeNode{Val: 9}, Right: &TreeNode{Val: 20, Left: &TreeNode{Val: 15}, Right: &TreeNode{Val: 7}}}, nil, {Val: 1}}
	for i, t := range trees {
		fmt.Printf("  0102 root=%s -> %v\n", specs[i], LevelOrder(t))
	}
	for _, g := range [][][]int{{{2, 1, 1}, {1, 1, 0}, {0, 1, 1}}, {{2, 1, 1}, {0, 1, 1}, {1, 0, 1}}, {{0, 2}}} {
		fmt.Printf("  0994 grid=%v -> ", g)
		fmt.Println(OrangesRotting(g))
	}
	for _, g := range [][][]int{{{2147483647, -1, 0, 2147483647}, {2147483647, 2147483647, 2147483647, -1}, {2147483647, -1, 2147483647, -1}, {0, -1, 2147483647, 2147483647}}, {{2147483647, 0, 2147483647}}, {{-1, -1}, {-1, -1}}} {
		fmt.Printf("  0286 grid=%v -> ", g)
		WallsAndGates(g)
		fmt.Printf("%v\n", g)
	}
	for _, g := range [][]string{{"@.a..", "###.#", "b.A.B"}, {"@Aa"}, {"...", ".Aa", "b@B"}} {
		fmt.Printf("  0864 grid=%v -> %d\n", g, ShortestPathAllKeys(g))
	}
}

5. 变体与边界 ​

  1. 状态里带别的历史（0815 Bus Routes）：节点从「站点」变成「站点 + 坐在哪辆车上」，visited 跟着变。
  2. 目标不是距离而是可达性（0200 Number of Islands）：BFS 照样能跑，只要坚持在入队时打标记，别在出队时才打。
  3. 多源但源点不同步（0317 Shortest Distance from All Buildings）：从每个房子各跑一次 BFS，还要记录每个格子离几号房子最近，状态里多带一个计数。
  4. 边权不一样（0743 Network Delay Time）：BFS 失效，换 Dijkstra；这也是「所有边代价相同」这个前提必须先确认的原因。
  5. 状态是数字串（0752 Open the Lock）：节点是锁的当前状态而不是位置，队列与 visited 都存状态编码。

6. 常见错误 ​

  1. 多源 BFS 边扫边扩散 → 后面的源点被推迟一轮，分钟数偏大。改法：先扫完全部源点再进主循环。
  2. 本轮新生成的节点继续在本轮扩散 → 一分钟内沿新格子传到底，答案偏小。改法：每轮用新切片收集，或先冻结 len(queue) 当轮次边界。
  3. 出队才打访问标记 → 同一节点被多次入队，队列爆掉。改法：入队的那一刻就标记。
  4. 只按格子去重（0864） → 拿着不同钥匙的同一格子被当成同一个，正确的路被剪掉，而且样例照样全过。改法：visited 的键用「位置 + 掩码」。
  5. 把「拿到所有钥匙」写成「打开所有锁」 → 目标判定错，答案偏大。改法：目标是掩码齐全。
