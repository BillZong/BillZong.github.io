## 0. 怎么用这份总结

1. **先看信号，再选算法**。每节开头是「适用信号」——题面出现这些特征，就往这一节翻。
2. **复杂度是硬约束**。同一题 O(n²) 与 O(n log n) 的差别，通常就是能不能过的差别。
3. **代表题不是题解**。表格只给「题号 → 关键点」，细节回 LeetCode 对应题目页看。

## 2. 基础数据结构与操作

### 2.1 数组与字符串

**本质**：连续内存 + 下标寻址。下标之差就是「距离」，下标本身就是状态。

**适用信号**：输入是一维序列；要求统计、比较、变换某个连续段；要求原地改。

**必会套路**

| 套路 | 做法 | 复杂度 |
| --- | --- | --- |
| 原地重排 | 快慢指针一趟扫描，不满足条件的就往后挪 | O(n) / O(1) |
| 前缀积后缀积 | 两趟遍历，不用除法避免除零 | O(n) / O(1) |
| 最大子段和 | Kadane：要么 DP，要么分治 | O(n) / O(1) |
| 找重复/缺失 | 原地打标记（下标当桶），或异或 | O(n) / O(1) |
| 字符串窗口 | 转成字符数组，窗口内维护计数 | O(n) / O(1) |
| 长串子串比较 | 滚动哈希（自然溢出）+ 双哈希防碰撞 | O(n) / O(1) |

**代表题**

| 题号 | 标题 | 难度 | 关键点 |
| --- | --- | --- | --- |
| 0001 | Two Sum | Easy | 哈希表把 O(n²) 降到 O(n) |
| 0121 | Best Time to Buy and Sell Stock | Easy | 一次遍历维护历史最小价 |
| 0238 | Product of Array Except Self | Medium | 前后缀积，不用除法 |
| 0152 | Maximum Product Subarray | Medium | 维护最大/最小两个乘积，负数会翻转 |
| 0283 | Move Zeroes | Easy | 快慢指针，原地保持相对顺序 |
| 0189 | Rotate Array | Medium | 三次反转，O(1) 空间 |
| 0228 | Summary Ranges | Easy | 只在边界处起新段 |

**易错**：交换两个元素时若用临时变量覆盖了还没读的值，元素就丢了；先和待交换位比较再决定。

---

### 2.2 哈希表与计数

**本质**：用「键 → 值」把查找从 O(n) 压到 O(1)。本质是**用空间换时间**，也是「记录已访问」的通用手段。

**适用信号**：需要判断重复、需要统计频次、需要记录「上次出现位置」、需要 O(1) 判存在。

**必会套路**

| 套路 | 做法 |
| --- | --- |
| 找配对 | 边遍历边查表，不要先全存再查 |
| 频次统计 | `map[K]int` 计数 + 一次遍历取最大/最小 |
| 位置记录 | `map[K]int` 存下标，用下标差算距离 |
| 分组 | `map[K][]T` 或先给键编号再开桶 |
| 连通性 | 并查集，见 4.4 |

**代表题**

| 题号 | 标题 | 难度 | 关键点 |
| --- | --- | --- | --- |
| 0001 | Two Sum | Easy | 最基本的查表补数 |
| 0128 | Longest Consecutive Sequence | Medium | 查表 + 每段只从起点延伸，O(n) |
| 0347 | Top K Frequent Elements | Medium | 计数后按频次分桶，倒着取第 K 桶 |
| 0560 | Subarray Sum Equals K | Medium | 前缀和作键、计数作值 |
| 0380 | Insert Delete GetRandom O(1) | Medium | 数组 + 哈希表做下标映射 |
| 0705 / 0706 | Design HashSet / Design HashMap | Easy | 开放寻址或拉链 |

**易错**：用 `map` 的键存可变对象（如 slice）会编译不过且语义错；键要选真正的不变量。

---

### 2.3 排序

**本质**：把数据按全序排好，让「相邻」变成一个可用的信息源。

**适用信号**：需要第 K 大/小；需要按位次处理；需要「排序后相邻配对」；要求稳定性的自定义比较。

**必会套路**

| 套路 | 做法 | 复杂度 |
| --- | --- | --- |
| 快速排序 | partition + 双指针 | 期望 O(n log n) |
| 归并排序 | 分治 + 合并；顺带求逆序对 | O(n log n) |
| 堆排序 | 建堆后反复取顶 | O(n log n) |
| 计数排序 | 值域有限时用桶 | O(n + k) |
| 第 K 大 | 快选（平均 O(n)）或大小为 K 的堆 O(n log K) | — |
| 自定义比较 | 多关键字时显式写比较器，别依赖排序稳定性 | — |

**代表题**

| 题号 | 标题 | 难度 | 关键点 |
| --- | --- | --- | --- |
| 0912 | Sort an Array | Medium | introsort：快排为主，递归深度超限切堆排 |
| 0075 | Sort Colors | Medium | 三路划分（荷兰国旗），一趟 O(n) |
| 0215 | Kth Largest Element in an Array | Medium | 大小为 K 的小根堆，堆顶即第 K 大 |
| 0493 | Reverse Pairs | Hard | 归并时统计跨半区的逆序对 |
| 1335 | Minimum Difficulty of a Job Schedule | Hard | 排序 + 动态规划（滚动） |
| 0164 | Maximum Gap | Hard | 桶排序，利用「答案至少是 (max-min)/(n-1)」 |

**易错**：用快排但 partition 写成「只有一端推进」，最坏退化成 O(n²)；递归深度也要控住。

---

### 2.4 链表

**本质**：节点串成的链，访问靠指针，插入删除 O(1) 但定位 O(n)。

**适用信号**：题目给出 head / 节点结构；要求反转、断链、合并；出现「倒数第 k 个」「找环」「找交点」。

**必会套路**

| 套路 | 做法 |
| --- | --- |
| 虚拟头节点 | `dummy := &Node{}`，消除「头节点特殊处理」分支 |
| 快慢指针 | 找中点、判环、找交点都靠它 |
| 反转链表 | 三个指针原地翻转；递归版要注意栈深 |
| 合并 | 按值大小顺序接指针 |
| 前后缀 | 反转后半段，再原地接回 |

**代表题**

| 题号 | 标题 | 难度 | 关键点 |
| --- | --- | --- | --- |
| 0206 | Reverse Linked List | Easy | 三指针迭代翻转 |
| 0021 | Merge Two Sorted Lists | Easy | 虚拟头 + 归并思路 |
| 0019 | Remove Nth Node From End of List | Medium | 快慢指针走 n+1 步 |
| 0143 | Reorder List | Medium | 找中点 + 反转后半 + 交替合并 |
| 0138 | Copy List with Random Pointer | Medium | `map[原节点]新节点` 两趟建表 |
| 0141 | Linked List Cycle | Easy | 快慢指针判环 |
| 0146 | LRU Cache | Medium | 哈希表 + 双向链表 |

**易错**：删除头节点和尾节点是两类分支；用虚拟头节点后，尾插要额外记 prev。

---

### 2.5 栈与队列

**本质**：栈是「后进先出」，队列是「先进先出」。两者都是**只暴露一端**的结构，于是「最近满足条件的元素」能被高效拿到。

**适用信号**：括号匹配、表达式求值、单调性维护、层序遍历、固定窗口最值。

**必会套路**

| 套路 | 做法 | 复杂度 |
| --- | --- | --- |
| 单调栈 | 存下标，入栈前把不满足单调性的弹出 | 每个元素各进出一次，O(n) |
| 单调队列 | 双端队列存下标，队首永远是当前窗口的最优 | O(n) |
| 括号匹配 | 左括号入栈，右括号出栈比对 | O(n) |
| 表达式求值 | 数字栈 + 运算符栈，或单栈 + 符号位 | O(n) |
| 层序遍历 | 队列按层推进，记 `len(q)` 切层 | O(n) |

**代表题**

| 题号 | 标题 | 难度 | 关键点 |
| --- | --- | --- | --- |
| 0020 | Valid Parentheses | Easy | 左入右出，类型必须匹配 |
| 0155 | Min Stack | Medium | 辅助栈存当前最小值 |
| 0739 | Daily Temperatures | Medium | 单调递减栈，弹出时算天数 |
| 0084 | Largest Rectangle in Histogram | Hard | 单调递增栈 + 宽度公式 |
| 0224 | Basic Calculator | Hard | 括号切换符号 + 栈保存中间值 |
| 0239 | Sliding Window Maximum | Hard | 单调递减队列 |
| 0232 | Implement Queue using Stacks | Easy | 一个栈存元素，一个栈做反转 |

**易错**：单调栈里存「值」还是「下标」决定了能不能算宽度；要算宽度就得存下标。

### 2.6 字典树

**本质**：把公共前缀合并成一棵树，让「前缀查询」退化成沿边走。

**适用信号**：大量字符串、查询以字符串前缀出现；统计以某串开头的数量；实现自动补全。

**必会套路**

- 节点存子节点 map + 结束标记 + 计数（计数用来做前缀统计）
- 插入 O(L)，查询 O(L)，L 为串长；空间 O(总字符数)
- 想省空间可以把 26 个孩子压成数组或位集

**代表题**

| 题号 | 标题 | 难度 | 关键点 |
| --- | --- | --- | --- |
| 0208 | Implement Trie (Prefix Tree) | Medium | 插入/查找/前缀匹配三件套 |
| 0211 | Design Add and Search Words Data Structure | Medium | 通配符 `.` 分支回溯 |
| 0212 | Word Search II | Hard | 字典树 + 在网格上 DFS，命中即剪枝 |

**易错**：查询 `.` 时若直接沿树往下走会漏解，必须允许分支枚举。

### 2.7 堆

**本质**：维护「当前最值」的容器。push/pop 是 O(log n)，取顶是 O(1)。只保证堆顶有序，不保证整体有序。

**适用信号**：Top K、第 K 大/小、流式最值、多路归并、任务调度。

**必会套路**

| 套路 | 做法 | 复杂度 |
| --- | --- | --- |
| Top K | 大小为 K 的小根堆，扫完取顶 | O(n log K) |
| 第 K 大 | 大小为 K 的小根堆，或快选 | O(n log K) / 平均 O(n) |
| 流式最值 | 固定大小堆，边来边挤 | O(log K) 每次 |
| 多路归并 | K 个有序序列各取堆顶 | O(N log K) |
| 任务调度 | 贪心 + 冷却时间统计 | — |

**代表题**

| 题号 | 标题 | 难度 | 关键点 |
| --- | --- | --- | --- |
| 0703 | Kth Largest Element in a Stream | Easy | 固定大小的小根堆 |
| 0023 | Merge k Sorted Lists | Hard | K 路归并 |
| 0621 | Task Scheduler | Medium | 贪心 + 公式/计数 |
| 0502 | IPO | Hard | 每次选「当前资金买得起且收益最大」的项目 |
| 0239 | Sliding Window Maximum | Hard | 单调队列（也可用堆，但 O(n log n)） |
| 1046 | Last Stone Weight | Easy | 大根堆反复砸 |

**易错**：Top K 用大根堆求第 K 小、或求 Top K 最大用了小根堆——方向搞反是最常见错法。

## 3. 基础算法

### 3.1 二分查找

**本质**：在**单调**的判定上做对数级收敛。前提不是「数组有序」，而是「答案落在左边或右边，且能 O(1) 判定」。

**适用信号**：答案空间是整数区间；要求最小值/最大值满足某条件；有序数组找边界。

**必会套路**

| 套路 | 做法 |
| --- | --- |
| 值域二分 | 在 `[lo, hi]` 上二分，判定函数单调 |
| 判定二分（最大化最小值 / 最小化最大值） | `check(x)` 可 O(n) 判定，二分 x |
| 找边界 | `lower_bound` / `upper_bound` 手写，注意 `mid` 偏哪边 |
| 旋转数组 | 先找断点（一个 O(n) 判断），再在对应半区二分 |
| 浮点/开区间 | 用 `while lo < hi` + `mid = lo + (hi-lo+1)/2` 避免死循环 |

**代表题**

| 题号 | 标题 | 难度 | 关键点 |
| --- | --- | --- | --- |
| 0033 | Search in Rotated Sorted Array | Medium | 每次判断哪半边有序 |
| 0034 | Find First and Last Position of Element in Sorted Array | Medium | 两次二分或一次二分双边界 |
| 0875 | Koko Eating Bananas | Medium | 判定二分：速度 x 能否吃完 |
| 0410 | Split Array Largest Sum | Hard | 判定二分：段和上限 x 是否可行 |
| 0004 | Median of Two Sorted Arrays | Hard | 二分在较短数组上切，保证左半不小于右半 |
| 0074 | Search a 2D Matrix | Medium | 展平成一维后二分 |

**易错**：`mid` 取下整还是上整，要和 `hi = mid` / `hi = mid - 1` 配套；混用就死循环。

---

### 3.2 滑动窗口与双指针

**本质**：把 O(n²) 的枚举「对撞」压缩成一次扫描。关键是**定义好循环不变量**：窗口里已经满足什么。

**适用信号**：连续子数组/子串的最长最短；需要「窗口内不重复/不超限」；两数之和的变体。

**必会套路**

| 套路 | 做法 | 复杂度 |
| --- | --- | --- |
| 固定长度窗口 | 右扩左缩，窗口长度固定 | O(n) |
| 可变长度窗口 | 右扩，条件破坏就左缩到刚合法 | O(n) |
| 对撞双指针 | 首尾夹逼（3Sum、盛水容器） | O(n) |
| 快慢指针 | 同向不同速（判环、去重） | O(n) |
| 跳过/原地 | 写指针与读指针分离 | O(n) |

**代表题**

| 题号 | 标题 | 难度 | 关键点 |
| --- | --- | --- | --- |
| 0003 | Longest Substring Without Repeating Characters | Medium | 窗口内字符不重复 |
| 0076 | Minimum Window Substring | Hard | 收缩到刚好合法的最小窗口 |
| 0424 | Longest Repeating Character Replacement | Medium | 窗口长度 - 最多字符数 ≤ k |
| 0011 | Container With Most Water | Medium | 对撞，移动短板 |
| 0015 | 3Sum | Medium | 排序 + 对撞 + 去重 |
| 0992 | Subarrays with K Different Integers | Hard | 至多 K 减 恰好 K |

**易错**：收缩条件写成「窗口不合法就缩」但没保证「缩到合法就停」，会漏掉更短的合法窗口。

---

### 3.3 前缀和

**本质**：把「区间求和」从 O(n) 变成 O(1)：区间和 = 两个前缀相减。

**适用信号**：问连续区间的和/和的某个性质；「和为 K 的子数组」；二维矩形区域和。

**必会套路**

| 套路 | 做法 |
| --- | --- |
| 一维前缀和 | `pre[i+1] = pre[i] + a[i]`，区间 `[l,r]` 和 = `pre[r+1]-pre[l]` |
| 前缀和作键 | `map[sum]count`，边遍历边查差值 |
| 前缀积 | 同理，注意 0 的处理 |
| 二维前缀和 | 建 `pre[i][j]`，矩形和 = 四项容斥 |
| 前缀异或 | `pre[i]^pre[j]` 得区间异或 |

**代表题**

| 题号 | 标题 | 难度 | 关键点 |
| --- | --- | --- | --- |
| 0560 | Subarray Sum Equals K | Medium | 前缀和 + 频次表 |
| 0303 | Range Sum Query - Immutable | Easy | 构造时算前缀和，查询 O(1) |
| 0308 | Range Sum Query 2D - Mutable | Hard | 二维树状数组或二维线段树 |
| 0525 | Contiguous Array | Medium | 前缀和 + 变体：0 记 -1 |
| 0724 | Find Pivot Index | Easy | 左右两趟求总和解 |

**易错**：前缀和表的下标约定（`pre` 长度是 n+1 还是 n）不统一，边界就会差一位。

---

### 3.4 递归与分治

**本质**：把大问题拆成同类小问题。递归是表达「规模递减」，分治是「拆 + 合并」。

**适用信号**：题面有「在区间里选」「合并两个有序序列」「求中位数」；需要把 O(n²) 降到 O(n log n)。

**必会套路**

| 套路 | 做法 |
| --- | --- |
| 归并 | 分到底再合并，合并时顺手统计跨区答案 |
| 折半 | 二分下标 + 一次 O(n) 判定 |
| 递归三要素 | 终止条件、递推式、答案合并方式 |
| 记忆化 | 同一状态只算一次，键要选对 |
| 快速选择 | partition 递归，只递归包含第 K 位的一侧 |

**代表题**

| 题号 | 标题 | 难度 | 关键点 |
| --- | --- | --- | --- |
| 0021 | Merge Two Sorted Lists | Easy | 迭代双指针 + dummy head（递归版要 O(L) 栈） |
| 0022 | Generate Parentheses | Medium | 递归时保证前缀合法（左括号数 ≥ 右括号数） |
| 0050 | Pow(x, n) | Medium | 快速幂，n 为负时取倒数 |
| 0327 | Count of Range Sum | Hard | 归并时统计跨半区贡献 |
| 0105 | Construct Binary Tree from Preorder and Inorder Traversal | Medium | 前序定根，中序切分，递归重建 |
| 0094 | Binary Tree Inorder Traversal | Easy | 显式栈迭代中序，避免深递归 |

**易错**：递归里做重复计算（应记忆化）；忘记终止条件导致栈溢出。

## 4. 遍历与图

### 4.1 深度优先搜索

**本质**：一条路走到底，走不动了回退。适合「把一个答案空间枚举完整」。

**适用信号**：连通块计数、枚举所有可能方案（选/不选、放置）、路径搜索、依赖关系判环。

**必会套路**

| 套路 | 做法 |
| --- | --- |
| 连通块 | 网格/邻接表上 DFS，每找到一个未访问节点计数 +1 |
| 回溯 | 维护「路径」，做选择 → 递归 → 撤销选择 |
| 拓扑判环 | DFS 三色标记：未访问/在栈上/已完成；遇到在栈上的节点即有环 |
| 剪枝 | 状态重复就停（记忆化）、答案已最优就停 |
| 方向枚举 | 四方向 / 八方向的偏移数组统一写 |

**代表题**

| 题号 | 标题 | 难度 | 关键点 |
| --- | --- | --- | --- |
| 0200 | Number of Islands | Medium | 迭代 DFS 标记已访问，连通块计数（递归易爆栈） |
| 0207 | Course Schedule | Medium | 拓扑排序入度法；判环用三色标记 |
| 0051 | N-Queens | Hard | 按行放置 + 三个布尔数组记录冲突列 |
| 0131 | Palindrome Partitioning | Medium | 回溯 + 预处理回文表 |
| 0212 | Word Search II | Hard | 字典树 + 网格 DFS |
| 0269 | Alien Dictionary | Hard | 建偏序图后拓扑排序 |

**易错**：回溯忘记撤销状态（`used[i] = false`），会把不同分支混在一起。

---

### 4.2 广度优先搜索

**本质**：按距离分层扩展，**第一次到达即最短**（无权图）。

**适用信号**：求最短步数/最短距离；按层输出；状态空间是一张隐式图。

**必会套路**

| 套路 | 做法 |
| --- | --- |
| 层序遍历 | 队列，按 `len(q)` 切层 |
| 最短路（无权） | BFS，第一次入队时记距离 |
| 状态压缩搜索 | 队列里存状态编码（位掩码、坐标对） |
| 双向 BFS | 两端同时扩，状态空间大时省一半 |
| 多源 BFS | 所有起点一起入队，等价于加一个超级源点 |

**代表题**

| 题号 | 标题 | 难度 | 关键点 |
| --- | --- | --- | --- |
| 0102 | Binary Tree Level Order Traversal | Medium | 队列按层切 |
| 0127 | Word Ladder | Hard | 单词当节点，邻接是「只差一个字母」 |
| 0994 | Rotting Oranges | Medium | 多源 BFS，按层计时 |
| 0286 | Walls and Gates | Medium | 多源 BFS 从门反向扩散 |
| 0752 | Open the Lock | Medium | 状态是环上的数字串 |
| 0864 | Shortest Path to Get All Keys | Hard | 状态 = 位置 + 已拿钥匙的位掩码 |

**易错**：BFS 里把节点入队时就标记已访问；写成出队才标记会重复入队，复杂度爆炸。

---

### 4.3 树

**本质**：层级结构，天然递归。关键只有三个：**定义清楚节点含义**、**确定返回什么**、**区分左右孩子的处理次序**。

**适用信号**：题目给出二叉树 / BST；求路径和、深度、直径、LCA；需要序列化。

**必会套路**

| 套路 | 做法 |
| --- | --- |
| 递归三状态 | 返回值（向上汇总）+ 参数（向下传递）+ 副作用（外部变量） |
| BST 性质 | 左小右大；中序遍历有序；验证时带上下界 |
| 路径问题 | 回溯累加路径和，回溯时减掉 |
| 直径 / 最大路径和 | 左右子树高度返回值 + 全局变量记录答案 |
| 层序遍历 | 队列，或 DFS 带上深度参数 |
| 序列化 | 前序 + null 标记，天然可还原 |

**代表题**

| 题号 | 标题 | 难度 | 关键点 |
| --- | --- | --- | --- |
| 0104 | Maximum Depth of Binary Tree | Easy | 递归或层序 |
| 0098 | Validate Binary Search Tree | Medium | 带上下界传播，不能只看父子 |
| 0235 / 0236 | Lowest Common Ancestor | Medium | BST 用大小关系，普通树用左右返回非空 |
| 0124 | Binary Tree Maximum Path Sum | Hard | 左右高度向上传，同时用全局量记过节点路径 |
| 0105 | Construct Binary Tree from Preorder and Inorder Traversal | Medium | 前序定根 + 中序定位 |
| 0297 | Serialize and Deserialize Binary Tree | Hard | 前序 + null 标记 |
| 1448 | Count Good Nodes in Binary Tree | Medium | 递归携带「祖先最大值/最小值」 |

**易错**：BST 验证只比较父子（`10,5,15` 会误判）；LCA 在普通树上把「一边为 null」当成没找到。

---

### 4.4 图

**本质**：节点 + 边。核心是三件事：**怎么表示邻接**、**怎么遍历**、**连通性怎么维护**。

**适用信号**：题目给边集或邻接表；求路径/顺序/连通分量；判断有无环。

**必会套路**

| 套路 | 做法 |
| --- | --- |
| 邻接表 | `[][]int`，无向图要双向都加 |
| 拓扑排序 | 入度为 0 的入队，出队时给邻居减入度；出队数 < n 说明有环 |
| Dijkstra | 优先队列 + 懒删除；边权非负 |
| Bellman-Ford / Floyd | 分别处理负权边、全源最短路 |
| 并查集 | 路径压缩 + 按秩合并，近乎 O(1) |
| 最小生成树 | Kruskal（排序边 + 并查集）或 Prim（堆） |

**代表题**

| 题号 | 标题 | 难度 | 关键点 |
| --- | --- | --- | --- |
| 0207 | Course Schedule | Medium | 拓扑排序 |
| 0743 | Network Delay Time | Medium | Dijkstra + 懒删除堆 |
| 0684 | Redundant Connection | Medium | 并查集，成环的那条边就是答案 |
| 0721 | Accounts Merge | Medium | 并查集 + 邮箱建索引 |
| 0547 | Number of Provinces | Medium | 并查集统计连通分量 |
| 0847 | Shortest Path Visiting All Nodes | Hard | 位掩码状态 BFS（积图），见 5.3 |

**易错**：无向图只加了一条边；Dijkstra 遇到负权边不成立（要用 Bellman-Ford）。

## 5. 范式与技巧

### 5.1 贪心

**本质**：每一步都选当前看来最好的，靠「局部最优能推导出全局最优」的证明支撑。**没有证明的贪心就是碰运气。**

**适用信号**：要求最大值/最小值且答案可以逐步构造；区间选择类；排序后按序处理。

**必会套路**

| 套路 | 做法 |
| --- | --- |
| 排序贪心 | 按某个键排序后按序处理（区间调度、糖果分配、任务冷却） |
| 交换论证 | 证明「把最优解里的两个元素交换不更差」，从而局部选择成立 |
| 反悔贪心 | 先按基线选，再回头修正（任务调度、合并区间） |
| 贪心 + DP | 贪心定顺序，DP 定数量（如 1335） |
| 区间选择 | 按右端点或左端点排序，贪心取不冲突的 |

**代表题**

| 题号 | 标题 | 难度 | 关键点 |
| --- | --- | --- | --- |
| 0055 / 0045 | Jump Game / Jump Game II | Medium | 贪心维护可达最远；II 用层数累加 |
| 0134 | Gas Station | Medium | 总和够就一定有解，否则无解 |
| 0763 | Partition Labels | Medium | 每个字母最后一次出现的位置决定段边界 |
| 0135 | Candy | Hard | 双向贪心取左右需求的较大值 |
| 0871 | Minimum Number of Refueling Stops | Hard | 堆 + 贪心（等价于 DP 转移的堆优化） |
| 0410 | Split Array Largest Sum | Hard | 贪心划分 + 判定二分 |

**易错**：只给「正确性靠交换论证」一句就过；面试里必须补上证明，否则和暴力没区别。

### 5.2 位运算与数学

**本质**：把整数当二进制看，用位运算替代算术。数学则是「把题目翻译成公式」。

**适用信号**：出现「只出现一次」「子集」「异或」「每个元素出现 k 次」；涉及整除、余数、进制、约数、质数。

**必会套路**

| 套路 | 做法 |
| --- | --- |
| 异或 | x^x=0、x^0=x；找唯一数、找缺失数 |
| 与或 | 提取某一位、判子集关系（`a & b == a`） |
| 移位 | `1 << k` 取第 k 位；防溢出用无符号右移 |
| 快速幂 | 指数按二进制拆，O(log n) |
| 状态压缩 | 用整数的二进制位表示「选了哪些」 |
| 数论 | 约数筛、质数判定、素数分解、模逆元 |

**代表题**

| 题号 | 标题 | 难度 | 关键点 |
| --- | --- | --- | --- |
| 0136 | Single Number | Easy | 全部异或 |
| 0190 | Reverse Bits | Easy | 逐位搬运 |
| 0371 | Sum of Two Integers | Medium | 不许用 +，用位运算模拟进位 |
| 0342 | Power of Four | Easy | 位掩码 + 排除 2 的幂特例 |
| 0493 | Reverse Pairs | Hard | 归并 + 位运算比较后缀 |
| 0292 | Nim Game | Easy | 博弈论：先手必赢 ⟺ 存在非零的 1 位 |
| 0263 | Ugly Number | Easy | 只含质因子 2、3、5 即为丑数 |

**易错**：右移有符号数会补符号位，要用 `uint` 或 `>>>` 语义。

### 5.4 设计类

**本质**：考的不是算法，是**接口设计 + 数据结构组合 + 复杂度承诺**。考的是「你能不能同时满足功能与性能要求」。

**适用信号**：题目要你实现一个类，含 add/remove/query 等多个操作。

**必会套路**

| 两个堆 | 流式中位数：大根堆存小的一半，小根堆存大的一半 |
| 单调队列 | 滑动窗口最值 |

### 5.5 模拟

**本质**：题目把规则写清楚了，照着实现。考的是**边界处理**与**代码组织**。

**适用信号**：题目描述一堆操作，问某个时刻的状态；「实现一个……类/方法」但没有性能要求。

**必会套路**

- 把状态显式建出来，不要散在多个变量里
- 操作顺序要真的模拟（有的题要求「恰好执行 k 次操作」，就按次循环）
- 边界值先写测试用例：空、单个、重复、全同

**代表题**

| 题号 | 标题 | 难度 | 关键点 |
| --- | --- | --- | --- |

| 0874 | Walking Robot Simulation | Medium | 方向状态机 + 边界判定 |
| 0068 | Text Justification | Hard | 贪心填充 + 最后一行左对齐 |

**易错**：把「模拟」当成「可以简化」；有时题目要求的就是逐步执行，跳步会错。

## 6. 数据库与 SQL

**本质**：SQL 是**声明式**的——描述「要什么」，不描述「怎么拿」。考的是对集合运算、窗口函数、连接语义的理解。

**适用信号**：给表结构和查询要求，返回一张表。

**必会套路**

| 套路 | 写法要点 |
| --- | --- |
| JOIN | `INNER` 取交集，`LEFT` 保留左表全部（配 `IS NULL` 找「没有」的） |
| 自连接 | 同表比父子关系（员工 vs 经理） |
| 分组聚合 | `GROUP BY` + `HAVING` 过滤聚合结果（不是 `WHERE`） |
| 窗口函数 | `ROW_NUMBER/RANK/DENSE_RANK` 排名、`LAG/LEAD` 取前后行 |
| 去重取第 N | `DISTINCT` + `ORDER BY` + `LIMIT`，或窗口函数 |
| 条件聚合 | `SUM(CASE WHEN ... THEN 1 ELSE 0 END)` 一行算多个指标 |
| 日期处理 | 按月/按日分组，注意格式 |

**代表题**

| 题号 | 标题 | 难度 | 关键点 |
| --- | --- | --- | --- |
| 0175 | Combine Two Tables | Easy | 一次 LEFT JOIN |
| 0181 | Employees Earning More Than Their Managers | Easy | 自连接 + 比较 |
| 0183 | Customers Who Never Order | Easy | `NOT IN` 子查询（等价于 LEFT JOIN + IS NULL） |
| 0185 | Department Top Three Salaries | Hard | 相关子查询 + `COUNT(DISTINCT 薪水)` |
| 0620 | Not Boring Movies | Easy | `WHERE` 取模 + 排除 boring |
| 1045 | Customers Who Bought All Products | Medium | `GROUP BY` + `HAVING COUNT(DISTINCT) = N` |
| 1179 | Reformat Department Table | Easy | 条件聚合 `SUM(CASE WHEN ...)` 手写 PIVOT |
| 1393 | Capital Gain/Loss | Medium | 买入/卖出折成一列后一次 SUM |
| 1965 | Employees With Missing Information | Easy | 两侧反连接 + `UNION` |

**易错**：`WHERE` 不能过滤聚合结果（要用 `HAVING`）；`LEFT JOIN` 的 `ON` 条件写错会把行数放大。

## 8. 选型速查

| 题面特征 | 先想到 |
| --- | --- |
| 有序数组找位置/边界 | 二分查找 |
| 求最小值使某个条件成立 | 判定二分 |
| 连续区间内的最长/最短/计数 | 滑动窗口 |
| 需要记录出现过什么 | 哈希表 |
| 求「第 K 大/小」 | 堆或快选 |
| 括号匹配、表达式 | 栈 |
| 最短步数、分层输出 | BFS |
| 枚举所有方案、找环 | DFS / 回溯 |
| 区间最值、前缀和查询 | 前缀和 |
| 求最优解且有重叠子问题 | DP |
| 每步选当前最好的 | 贪心（记得给证明） |
| 多个操作、要求每次 O(1)/O(log n) | 设计类 |
| 只要唯一解/存在性 | 位运算、数学、哈希 |
